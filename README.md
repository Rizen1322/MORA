# AutoMix

Музыкальный плеер для своих файлов с DJ-переходами (AutoMix) и персональной «Моей волной». Интерфейс на русском.

## Приложение MORA для Windows

С 0.3.14 доступно обновление через GitHub Releases: автоматическая проверка, загрузка по кнопке и установка после подтверждения перезапуска. С 0.3.13 первый переход выполняется вручную. [Поведение и выпуск обновлений](docs/desktop-auto-update.md).

Отдельное приложение без терминала, системных Node/Python/FFmpeg: установщик `apps/desktop/dist/MORA-Setup-0.3.8.exe` или папка `apps/desktop/dist/win-unpacked` (запуск `MORA.exe`). CPU-модель для подготовки вокала включена в установщик. Сборка:

```bash
npm install
node apps/desktop/scripts/fetch-ffmpeg.mjs
node apps/desktop/scripts/fetch-ytdlp.mjs
node apps/desktop/scripts/fetch-vocals.mjs --python <путь-к-Python-3.12-на-машине-сборки>
npm run desktop:package
```

Без аккаунтов: поиск и прослушивание публичных записей YouTube Music, YouTube и SoundCloud, импорт плейлистов Spotify/Apple Music/YouTube/файлов, загрузки для офлайна, тексты, 10-полосный эквалайзер, онлайн-радио. Подробно: [docs/public-sources.md](docs/public-sources.md).

Текущая 0.3.8: быстрый поиск SoundCloud, резервный поиск YouTube Music, публичные страницы артистов/альбомов и выбор AutoMix-плана с защитой первых слов. [Проверка поиска и каталога](docs/pc-release-0.3.7.md), [изменения AutoMix](docs/pc-release-0.3.8.md).

В 0.3.0: независимые скорость и высота тона, автономный вокальный компонент и проверки реальных переходов. [Отчёт](docs/mora-audit-0.3.0.md).

Медиатека приложения хранится в `%LOCALAPPDATA%\MORA\data`; прежнюю папку (`data-dev`) можно перенести в «Настройки → Перенести медиатеку». Архитектура, проверки и ограничения: [docs/desktop-windows.md](docs/desktop-windows.md).

## Запуск (Windows, macOS, Linux)

Нужны Node.js ≥ 22.13 и ffmpeg/ffprobe в PATH (или пути в `.env`).

```bash
npm install
npm run build
npm start
```

Откройте http://localhost:4730 и перетащите в окно файлы или папку. Демо-треки (синтезированы самим проектом): `npm run demo:tracks` → `examples/library`.

В этой рабочей папке `.env` указывает на существующую медиатеку `data-dev`, чтобы сохранить импортированные ранее треки. При новой установке путь по умолчанию — `data`; его можно изменить через `AUTOMIX_DATA_DIR`. Режим разработки: `npm run dev` (backend 4730, Vite 5173).

Тесты: `npm test`. Оценка переходов: `npm run eval:transitions -- --json docs/validation-matrix.json` (или передайте папку со своими файлами). Примеры переходов: `npm run demo:transitions` → `examples/transitions`. Проверка типов: `npm run typecheck`.

## Что внутри

- `packages/core` — DSP/MIR-ядро без зависимостей: анализ (BPM с half/double, биты, доли, фразы, тональность, громкость BS.1770, тишина, эвристика плотности середины — не детектор голоса), планировщик `TransitionPlan`, микшер на двух деках (WSOLA с сохранением тона и защитой атак, 3-полосный LR4-изолятор, эхо, лимитер), рекомендатель «Моей волны».
- `apps/server` — Fastify + `node:sqlite` + ffmpeg: импорт, метаданные и обложки, кэш PCM, фоновый анализ в worker threads, планы и журнал переходов, плейлисты, история, очередь, адаптеры источников.
- `apps/web` — React + Vite; тот же микшер работает в AudioWorklet, переходы считаются по счётчику сэмплов.

Методы переходов: сведение по битам с плавным переходом темпа обеих дек (tempo glide, по умолчанию до 12 % для каждой деки, 1–16 тактов, обмен басом), мост к промежуточному темпу с возвратом следующего трека к исходному BPM, **DJ drop** с инструментальной подводкой и сменой баса на сильной доле, эхо-переход, адаптивный кроссфейд, без паузы для альбомов, короткий срез в режиме «Короткие».

**DJ-сведение вокала** использует локально выделенную партию Hybrid Demucs: старый голос уходит перед вступлением нового, пока инструментал продолжает переход. Партия и исходник проходят один стерео time stretcher. Для несовместимых BPM DJ drop сохраняет собственный темп треков и меняет грув на выбранной сильной доле. Если глобальная сетка неустойчива, планировщик проверяет измеренные локальные участки ритма. Подробности, установка и ограничения: [docs/dj-automix.md](docs/dj-automix.md).

«Умный вход» оценивает начало, фразы и структурные границы следующего трека, включая участки на 20–30 секунде. По умолчанию можно пропустить до 45 секунд вступления; предел настраивается от 0 до 75 секунд. «Сохранять начало» оставляет слышимое начало трека. В плеере и диагностике видны реальные точки входа/выхода и объяснение выбора.

Настройки применяются и к уже подготовленной паре. Изменения очереди отменяют устаревшую подготовку; перемотка назад повторно загружает вытесненный PCM. Skip и seek во время наложения сохраняют затухание второй деки.

Первое нажатие «Следующий» запускает короткое сведение из текущего места. Повторное нажатие или «Не нравится» переключает быстро. Поведение можно отключить настройкой «Сводить по кнопке “Следующий”». Новая точка входа загружается до запуска перехода.

Проверка импортированной библиотеки: `npx tsx tools/audit-library.ts --analyze --render --pairs 64 --tag current`. Планируются все направленные пары; рендер ограничен равномерной выборкой с покрытием библиотеки. Демо исключаются по хешу содержимого, отчёт сохраняется в папке данных `reports/`. Для проверки кнопки Next добавьте `--manual --at 0.5`; `--pairs all` рендерит всю матрицу, `--resume` продолжает контрольные точки. Исходные пользовательские файлы не копируются в примеры. Исторический разбор первых пяти треков: [docs/real-library-validation.md](docs/real-library-validation.md).

Исследование Apple: [docs/apple-automix.md](docs/apple-automix.md). Apple подтверждает AI-анализ, beat matching и time stretching, но не публикует внутренние модели и точные алгоритмы AutoMix. Здесь собственный DSP/MIR с необязательным локальным нейросетевым разделением вокала. Базовый плеер работает без Python/GPU; расширенное DJ-сведение требует готовых партий. Границы секций не являются распознаванием припева; плотность середины не является детектором вокала. Сетка фраз предполагает 4/4. Сложное сведение выбирается по уверенности, поэтому каждая пара проходит планировщик, но не каждая растягивается по BPM.

Проверки и ограничения: [docs/validation.md](docs/validation.md). Аудиопримеры синтетические; численная проверка и работа браузера не заменяют прослушивание реальной библиотеки человеком.

## Источники

Свои файлы — полностью. Navidrome/Subsonic, Jamendo — адаптеры, нужны ваши адрес/ключ. Audius — с этого компьютера API отвечает 403. **Яндекс Музыка — экспериментальный импорт полного MP3, поиск/лайки/ссылки, подготовка волны и AutoMix с локальными вокальными партиями**. Нужен доступ к полной записи в аккаунте; превью и зашифрованные варианты не поддерживаются. Реальный импорт, анализ и PCM-перемотка проверены: [инструкция](docs/yandex-integration.md). Spotify не подключён к нашему движку: его публичный API не предоставляет нужный режим; официальные партнёрские DJ-интеграции и альтернативные клиенты разобраны в [исследовании](docs/streaming-sources-followup.md). Исходный обзор: `docs/research.md`.

## Лицензии

Собственный код проекта. Зависимости: React, Vite, Fastify, music-metadata, zustand (MIT), Phosphor Icons (MIT), шрифты Inter и Oswald (SIL OFL), ffmpeg (системный, LGPL/GPL в зависимости от сборки — не входит в репозиторий). Необязательные PyTorch/Torchaudio поставляются отдельно; используется официальный bundle Hybrid Demucs (код Demucs — MIT). Коэффициенты K-фильтра по схеме libebur128 (MIT). GPL/AGPL-компоненты (Mixxx, Essentia, Rubber Band, MATLAB Tempogram Toolbox) не включаются.

## Телефон

Сейчас: адаптивный веб-интерфейс, доступ из локальной сети через `HOST=0.0.0.0` и `ACCESS_TOKEN`; MediaSession даёт кнопки на экране блокировки в Android Chrome. Надёжный фоновый AutoMix в PWA/WebView не гарантирован: для iOS/Android нужен нативный аудиодвижок (AVAudioEngine / Oboe), куда переносится `packages/core` (чистый TS без зависимостей, контракт `TransitionPlan`), а backend остаётся как сервер медиатеки или переносится анализ на устройство.
