# Промпт для Claude: самостоятельный музыкальный клиент с возможностями Riff

Ниже готовое задание для Claude, который работает с актуальным репозиторием. Главный приоритет уточнён пользователем: поиск и прослушивание музыки без обязательных аккаунтов и подключения Яндекса. Поиск другой версии — дополнительная функция.

---

Продолжи наш музыкальный проект в `E:\вин\ПРОЕКТЫ\music` и преврати его в самостоятельный музыкальный клиент. Изучи https://github.com/rootscripts/riff и перенеси много полезных идей с адаптацией к нашей архитектуре, дизайну и качеству звука. Не заканчивай на исследовании или мокапе: реализуй работающие сценарии, проверь их и подготовь сборку.

## 1. Главная цель: музыка без обязательных аккаунтов

Главный сценарий: человек устанавливает приложение, открывает поиск, вводит исполнителя/название, нажимает Play и слушает. Ему не нужны аккаунт приложения, токен Яндекса, Spotify Client ID, подписка или запуск отдельного сервера вручную. Интернет для удалённых источников, разумеется, нужен. Собственные и скачанные треки работают офлайн.

Первичные источники — доступные публичные записи YouTube Music/YouTube и SoundCloud по подходу Riff. Яндекс сохранить как необязательный дополнительный источник со своей персонализацией, лайками и настройками волны. Отсутствие Яндекса не должно блокировать приложение, поиск, главную, коллекцию или AutoMix. Не предлагай подключить Яндекс вместо реализации свободного поиска.

Раздели три понятия: откуда получены метаданные, откуда фактически играет звук, какая конкретная запись выбрана. Импорт списка из Spotify/Apple Music не означает, что аудио пришло из Spotify/Apple Music. В интерфейсе честно показывай реальный источник и версию записи.

Не обещай, что каждый публичный трек в любой стране всегда доступен без входа: обработай недоступность, удаление, ограничения источника, таймауты и требования авторизации. Покажи понятную ошибку и другие результаты. Не пытайся обходить DRM, платный доступ или CAPTCHA. Используй доступные записи и отдельно проверь условия выбранных интеграций.

Репозиторий активно изменялся Claude и Codex; код важнее старых handoff. Не делай git reset/clean, не удаляй untracked исходники, не очищай пользовательскую базу, плейлисты, `.env` и токены. Пользовательские данные не использовать для разрушающих тестов.

Riff уже исследован на commit `add6843dc57cc86a93a1692c8c339bba4f9099c2`; reference checkout может быть в `tools/.cache/riff-reference`. Проверь актуальный upstream и зафиксируй изученную версию. Основные файлы: server.js, app.js, audio-engine.js, platform.js, main.js, preload.js, themes.js, track-sort.js, search-text.js, library-tools.js, README.md и LICENSE.

Отдельно учитывай лицензии зависимостей и распространяемых бинарников. Не копируй слабые места: отключение проверки TLS, неограниченные кэши, выбор первого похожего результата, фиксированный порт, синхронные большие файловые операции и замалчивание ошибок. Рекламные формулировки README проверяй по фактическому коду.

## 3. Провайдеры и получение звука

Сохрани/расширь общий provider contract: capabilities, search, resolve, получение аудио, доступность seek/download/PCM/mixing, error classification. Добавь YouTube Music/YouTube и SoundCloud. Не дублируй поиск, downloader и обработку ошибок отдельно на каждой странице.

Для desktop пригоден локальный resolver на yt-dlp, как у Riff. На чистой машине всё должно работать из установленного приложения: нужный бинарник упакован либо устанавливается приложением из проверенного официального источника. Проверь требования выбранной версии yt-dlp к JS runtime/дополнительным компонентам, FFmpeg и архитектуре ОС. Не рассчитывай на заранее установленные Python, Node, yt-dlp и FFmpeg. Обновление resolver — управляемое, атомарное, с проверкой целостности и возможностью отката, без запуска случайных файлов из результатов поиска.

Вызывай subprocess через execFile/spawn с массивом аргументов и shell:false. Пользовательский запрос не становится shell-командой; фиксируй допустимые опции, заверши опции до переданного URL. Валидация URL/host/redirect, запрет доступа к внутренней сети через публичный resolver/proxy, обычная TLS verification, timeout, cancel и ограничения размера ответа обязательны. Не передавай чужим CDN OAuth-токены Яндекса или внутренний launch token приложения.

Ссылки на потоки временные: учитывай expiry, не сохраняй signed URL как постоянную идентичность трека. Храни provider+externalId+canonical URL. Resolve singleflight, TTL cache с лимитом, retry/backoff; при истечении ссылки обновляй её без бесконечного цикла. Отмена поиска или смена очереди отменяет устаревшие работы.

Web frontend должен использовать backend adapter, а не пытаться spawn yt-dlp в браузере. Desktop backend работает локально и запускается оболочкой; арендуемый сервер не нужен. Не ломай существующую поддержку web-режима.

## 4. Единый поиск

Сделай поиск сразу пригодным для повседневного использования:

- Ввод по названию, артисту, альбому; вставка ссылки на трек/альбом/плейлист.
- Источник «Все» по умолчанию; отдельные фильтры YouTube Music, YouTube, SoundCloud, своя музыка, Яндекс при подключении.
- Debounce, отмена старого запроса, ограниченная параллельность. Медленный источник не задерживает уже готовые результаты других.
- Результаты показываются постепенно, без смены списка под курсором и скачков выделения. Retry только провалившегося источника.
- Название, артист, обложка, длительность, источник, версия, доступное качество. Официальный артист/канал — только при наличии реального признака.
- Хорошее ранжирование: соответствие артисту и названию, длительность, версия, тип результата. Не выводи случайный cover/reaction/remix выше нужной песни только из-за просмотров.
- История поиска и недавние результаты локально; очистка пользователем. Кэш ограничен, приватные запросы не уходят в аналитику.
- Кириллица, ё/е, Unicode, различия регистра и пунктуации, feat и разные написания исполнителя обрабатываются аккуратно. Не стирай meaningful version tags ради fuzzy matching.
- Enter запускает выбранный результат, стрелки меняют выделение; есть Play next, Add to queue, Like, Add to playlist, Download, Artist, Album и контекстное меню.

Не делай обязательным добавление каждого результата в пользовательскую медиатеку перед прослушиванием. Если внутренний pipeline требует TrackRow, создай техническую запись, отличай её от явного сохранения и не загрязняй «Недавно добавленные» всей историей поиска. Очередь и сохранённая коллекция — разные пользовательские действия.

## 5. Быстрый старт и совместимость с AutoMix

Новый публичный источник должен проходить через наш полноценный audio engine, а не становиться вторым несогласованным HTMLAudio-плеером. Исследуй поддержку контейнеров/кодеков и PCM decode. Где возможен progressive start — реализуй его с корректным seek/range; где нет — честно показывай короткую подготовку и измерь задержку.

Раздели готовность к прослушиванию и готовность к сложному сведению. Трек может начать играть до завершения MIR/stems. Пока точных данных нет, безопасный переход; по мере готовности обновляй будущие планы. Не объявляй битовое сведение или vocal isolation готовыми по одному названию трека.

Приоритеты: звучащий трек → ближайший следующий → следующие рекомендации → фоновые downloads → остальная библиотека. Заранее разрешай URL, подготавливай ограниченный PCM reserve и анализ следующей пары. Не запускай separation всего найденного каталога и десятки subprocess одновременно.

Сохрани текущие исправления: f32 headroom, single/shared WSOLA для согласованных компонентов, ограничения входа и выхода, bounded PCM windows, stem generation/reset ACK, транспортные intent revisions. Не прикрепляй старый beat grid/stems к новому аудиофайлу по совпадению title. При пропуске или смене источника старые асинхронные результаты не меняют текущий трек.

## 6. Дополнительная функция «Найти другую версию»

Это важная дополнительная функция, но не главный экран и не замена общему поиску.

В меню любого трека — «Найти другую версию». Открой полноценную боковую панель или лист, на мобильном — удобный bottom sheet. Заполни запрос артистом и названием, разреши редактирование и выбор источников. Дай быстро найти original/explicit/uncensored, clean/radio edit, album version, remix, live, slowed и собственный файл.

Покажи карточки кандидатов с длительностью, фактическим источником, uploader/artist и version labels. Непроверенное «uncensored» из пользовательского заголовка не равно подтверждённому отсутствию цензуры. Explicit metadata тоже не доказывает, что все слова сохранены. Различай «так указано источником», «предположение по названию» и «выбрано пользователем». Не обещай AI-проверку цензуры без реализованной и проверенной технологии.

Предпрослушивание — без наложения двух песен. Сохраняй исходный трек и позицию, приостанавливай его, давай seek внутри кандидата. После закрытия восстанавливай только если пользователь сам не изменил транспорт/очередь. Не требуй полного separation для прослушивания отрывка. Сравнение с выравниванием воспринимаемой громкости возможно как явно обозначенная настройка; громче не означает лучше.

После выбора варианты: «Только сейчас», «Использовать для этого трека», «Добавить отдельно», «Вернуть исходную запись». Замена источника не теряет лайк, плейлисты, порядок и историю. Исходный файл/remote reference не удаляй. Пользователь может отменить выбор. Для реально другой записи предложи добавить отдельно вместо скрытой склейки идентичностей.

Проектируй связь логического трека и конкретного audio asset/source binding. Analysis/stems/lyrics offsets/normalization относятся к конкретному recording content hash и версии анализа; лайки/плейлист — к пользовательской сущности. Смена аудио публикуется атомарно после проверки, инвалидирует будущие планы/PCM/stems, но не обрывает уже звучащий blend. Не переносит старую позицию автоматически, если у другой записи иное вступление/таймлайн.

Яндекс feedback получает только реальную атрибуцию соответствующего прослушивания. Если фактически играет YouTube-версия, не отправляй Яндексу выдуманный trackStarted для неё. Семантику лайка логического трека и синхронизации исходного Яндекс-трека явно отдели от источника звука.

## 7. Эквалайзер и звук

Полезный ориентир Riff — 10 полос и пресеты. Сделай удобную панель «Звук» в плеере:

- 10-полосный графический EQ примерно31/62/125/250/500/1k/2k/4k/8k/16kHz, с корректным ограничением частот относительно Nyquist.
- Диапазон усиления разумный, например±12dB; плавное изменение без clicks, управление мышью/клавиатурой, ввод значения, double click reset.
- Общий bypass, Flat/reset, сохранение пользовательских пресетов. Несколько полезных умеренных пресетов: бас, вокал, тихое прослушивание, электронная музыка.
- Preamp и контроль headroom. Не обещай защиту от clipping простым вычитанием максимального поднятого slider: суммарный отклик фильтров нужно учитывать/измерять. После всей пользовательской обработки — корректная финальная защита true peak и разумный ceiling, без двойной жёсткой компрессии.
- EQ пользователя работает после внутреннего DJ-суммирования, не подменяет transition EQ handoff и не переписывает исходный анализ громкости. Пересмотри расположение master volume/limiter так, чтобы усиление за лимитером не возвращало clipping.
- Нормализация громкости, баланс L/R, mono, управление устройством вывода там, где реально поддерживается. Не требуй разрешение микрофона ради обычного воспроизведения. Если выбор output API недоступен — понятный fallback.
- Speed и независимый pitch — расширенная панель, не три одинаковых способа случайно растянуть звук. Если пользователь меняет темп, AutoMix учитывает реально применённую скорость; никакого двойного time stretch и рассинхронизации stems.
- Reverb/echo/saturation необязательны и по умолчанию выключены. Не называй saturation/HQ preset улучшением исходного качества или восстановлением потерянных частот.

На loud bass-heavy треках, hot masters и одновременном blend не должно появляться прежнего «храпа». Проверяй PCM peak/true peak/NaN/underruns, а не только наличие красивого EQ UI. Все параметры сохраняются, миграции настроек обратимы и имеют корректные defaults.

## 8. Офлайн и downloads

Сделай нормальный менеджер загрузок, полезнее простого бесконтрольного cache:

- Скачать трек/плейлист, прогресс по каждому файлу, ограниченная параллельность, pause/cancel/retry, очередь при возврате сети.
- Отдельные состояния загрузки и подготовки AutoMix. Музыка уже доступна офлайн, даже если stems ещё считаются.
- Папка загрузки, Wi-Fi/объём по возможностям платформы, свободное место, размер cache, ручная очистка только cache.
- Скачанное пользователем pinned; LRU его не удаляет. Текущий и следующий треки тоже защищены от eviction.
- Временный файл → проверка контейнера/длительности → атомарная публикация. Ошибка/выход приложения не оставляют «готовый» файл из половины записи.
- Предпочитай исходный доступный audio format без лишних перекодирований. MP3→FLAC не становится lossless-оригиналом; UI не должен утверждать обратное.
- Сохраняй cover/metadata/source manifest, показывай версию и качество. Не извлекай аудиокэши других приложений и не обходи DRM.
- В авиарежиме доступны скачанные песни, поиск по ним, коллекции и локальная волна. Онлайн-подбор не изображается работающим без сети.

## 9. Импорт коллекций

Возьми идею Riff: импорт публичных Spotify/Apple Music/YouTube/SoundCloud плейлистов, плюс пользовательские JSON/CSV/M3U exports. Яндекс — по возможностям текущего адаптера. Подключение аккаунта для приватных данных опционально; без входа пользователь всё равно может искать и слушать музыку.

Импортирует metadata, затем сопоставляет с выбранным источником. Сохраняй порядок, pagination, повторы там, где они намеренные, корректное количество найденных/не найденных. Не показывай100% успех, если parser увидел только первые30 из200.

Разделяй high-confidence match и сомнительный. ISRC при наличии, артист, название, version tags, длительность, альбом — признаки. Не выбирай remix/live/cover вместо album version молча. Неразрешённые позиции остаются понятными placeholder rows с ручным поиском, а не исчезают. Кандидатные поиски кэшируются, повторы не запускают одинаковые запросы.

Сначала покажи предпросмотр и отчёт, затем создавай/обновляй плейлист. Resume после перезапуска, отмена и идемпотентность: повторное нажатие не создаёт десять копий. Частичные ошибки одного источника не откатывают всё и не портят существующие коллекции.

## 10. Тексты песен

Синхронные тексты и караоке по примеру Riff: LRCLIB при доступности, локальные LRC/plain text, локальный cache. Учитывай исполнителя, название и длительность; первый результат поиска не гарантирует правильную песню. Отличай отсутствующий текст от сетевой ошибки.

Подсветка текущей строки, клик для seek, ручной offset с сохранением для конкретной записи, включение/отключение следования за строкой. Не вырывай пользователя из ручного скролла. Красивое крупное чтение, reduced motion, keyboard access. Plain text тоже нормально отображается.

Публичные lyrics/LRC тайминги предназначены для интерфейса. Не подменяй ими автоматически достоверную vocal activity в нашем AutoMix. ASR/stem-verified voice masks и пользовательская караоке-синхронизация — разные данные. Перевод — опциональный, с явным поставщиком; не отправляй тексты/историю на неизвестный сервис скрытно.

## 11. Радио и рекомендации без аккаунта

Добавь режим свободной волны без Яндекса: от трека, артиста, жанрового запроса и локального вкуса. Используй реально доступные related/mix результаты адаптеров и локальные лайки/пропуски. Не называй простую формулу нейросетью и не выдумывай персонализацию сервиса.

Дедупликация recording IDs, контроль повторов и концентрации одного артиста, dislikes, recent history, familiar/discover баланс. Подготовка следующего ограниченного резерва идёт до окончания текущих4 песен. Ошибки одного кандидата не обрывают эфир. Яндекс-волна сохраняет собственные настройки/session feedback, не смешивай их с локальной историей автоматически.

Главная без Яндекс-аккаунта должна быть полезной: поиск, продолжить слушать, свободная волна, любимое, скачанное, недавние коллекции. Реальные данные вместо выдуманных персональных рекомендаций/счётчиков.

## 12. Дизайн и повседневные удобства

Сохрани нашу хвойную тёмную палитру и текущую идентичность; не копируй весь Material Design3 Riff. Возьми полезные принципы: тональная реакция на обложку, чёткая иерархия, выразительная активная кнопка, компактный режим, продуманные состояния и доступные настройки. Цвета обложки мягко примешиваются к фирменным цветам, контраст текста сохраняется. Если пользователь ещё не утвердил название — не переименовывай приложение произвольно.

Главная: большая центральная волна/персональный эфир, остальное компактнее; заметный поиск доступен сразу. Мини-плеер, dock и fullscreen дают одинаковый транспорт. «Звук», «Текст», «Очередь» открываются предсказуемо, не создают три перекрывающихся модальных окна и не закрываются на каждом новом треке.

Полезные дополнительные функции:

- Таймер сна:15/30/60min, своё время, до конца трека/очереди; мягкий fade, отмена, корректная работа при AutoMix overlap и sleep/wake. Не увеличивать сохранённую громкость после завершения.
- Компактное desktop окно/мини-плеер с настройкой always-on-top, без потери позиции; fullscreen lyrics mode.
- Горячие клавиши, MediaSession/media keys, нативное системное меню, drag/drop файлов и ссылок, удобный поиск/командное меню.
- Discord Rich Presence исключительно opt-in, настройка скрытия названий, при выключении никакого скрытого подключения/публикации статуса.
- Умные локальные подборки: недавно добавленное, давно не слушал, скачанное, любимое; сортировки/поиск/выделение нескольких треков и пакетные действия.
- Экспорт/резервная копия плейлистов и настроек, перенос данных без перезаписи файлов пользователя.
- Ограниченный визуализатор, управляемая анимация прогресса, несколько разумных настроек плотности/масштаба/темы; CSS editor и произвольные плагины не приоритет, не открывай ради них произвольное выполнение кода.
- Если делаешь audio trimming/export: оригинал неизменен, файл отдельно; stream-copy ограничен контейнером и точками резки, не обещай одновременно sample accuracy и lossless без перекодирования. Это поздний этап после стабильного поиска/плеера.

Используй фактически имеющиеся local skills, текущие React/CSS/Three.js компоненты. Не ставь сразу шесть animation frameworks. Анимация не мешает seek/keyboard, не грузит свёрнутое окно, respects reduced motion. Измеряй FPS/CPU/RAM вместо обещаний. Все настройки читаемы и понятны обычному слушателю; диагностика — отдельно.

## 13. Архитектура и оптимизация

Сеть/resolver/FFmpeg/ML не выполняются на audio thread и не блокируют Electron main/renderer. На процессы — лимиты, очереди приоритетов, таймауты, отмена и очистка после выхода. Signed URLs/секреты не пишутся в логи. Backend только loopback, desktop launch token сохраняется в защищённом bridge, не передаётся сторонним потокам. Соблюдай существующую context isolation/sandbox модель.

Модули небольшие: providers, resolver/download scheduler, catalog matcher, source bindings, lyrics, sound settings, UI panels. Не складывай всё в controller.ts. Целостность между logical tracks/audio assets/cache/analysis — явные контракты и миграции. Копии одних и тех же аудиоданных не хранятся бессмысленно по пять раз.

Мерь cold start, search latency per provider, first audio, next-track gap, peak RSS, CPU при playback/analysis, underruns, длительность подготовки пары и объём cache. Проверь библиотеку хотя бы на нескольких тысячах записей, не загружай всю дискографию/стемы в RAM.

## 14. Реализация и проверка

Работай этапами, но доводи каждый до работающего пользовательского сценария:

1. Аудит и минимальный сквозной сценарий: clean install → поиск без аккаунта → playable source → звук через наш engine → queue/next/seek.
2. Стабильные YouTube/SoundCloud adapters, stream expiry/retry, reserve/prefetch и AutoMix.
3. Search UI, сохранение треков/плейлистов и функция выбора альтернативной записи с preview/undo.
4. EQ/headroom и downloads/offline.
5. Импорт коллекций, lyrics, свободная волна.
6. Таймер, мини-плеер и остальные удобства, оптимизация/полировка.

При доступных агентах можно делегировать независимые области provider/resolver, sound/DSP, UX/collections, но назначь владельцев файлов и интегрируй изменения сам. Не допускай одновременного переписывания controller/DB несколькими агентами.

Проверь реальные публичные источники и офлайн fixtures; CI не должен зависеть от текущего YouTube. Regression tests: expired URL, timeout, partial download, old search response, wrong recording/version, source replacement during active blend, preview close after manual Pause/Next, no-account launch, offline queue, import pagination and resumption, EQ bypass/true peak and no clipping. Для нового audio asset старые analysis/stems никогда не используются.

Прогони актуальные typecheck/build/test и packaged smoke. Для desktop проверь работу без глобальных developer tools, отсутствие лишних процессов после выхода, media keys, tray, sleep/wake. Сохрани скриншоты и фактические метрики. Не утверждай, что прослушал звук, если только прогнал unit tests.

Не меняй молча user reactions/подписки/удалённые плейлисты ради тестирования. Сетевые smoke делают минимальное количество запросов и не скачивают гигабайты.

В финале дай работающую сборку/команды запуска, что реально реализовано, какие источники протестированы, какие ограничения остались, ссылки на изменённые файлы и список следующей работы. Нельзя назвать задачу готовой, если доступны только красивый поиск и моки, а без Яндекс-токена музыка не играет.
