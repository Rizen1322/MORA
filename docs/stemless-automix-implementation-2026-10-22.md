# AutoMix без стемов: внедрение P1–P10

Дата: 22 октября 2026 года. Основание: [исследование](mobile-stemless-automix-research-2026-10-22.md). Версии: `am-analyzer-13`, `am-planner-v12-fullmix-2`.

## Граница изменений

Новые правила включаются, когда голос хотя бы одного трека **неизвестен**:
- у трека нет вокальной карты;
- или выключено `stemMixing`.

Это iPhone, треки до разделения и ПК без нейросети. Если у обоих треков есть карты и стемы включены, планы прежние: из 75 таких пар библиотеки не изменилась ни одна. Неизвестный голос нигде не считается тишиной и не даёт бонуса «нет вокала».

## Что сделано

| Пункт | Где | Что |
|---|---|---|
| P1 | `plan/planner.ts`, `chooseFullMixPlan` | Базовый план и до трёх альтернатив: вдвое короче (16 → 8 тактов, минимум 4; только при техническом провале базового плана или шатком пульсе), соседний выход на фразу в 4–8 тактах с той же длиной, без стыковки ритмов (только при неуверенном пульсе: работающее сведение по битам сохраняется); B со своего начала (не ценой потери сведения по битам). Оценка — `fullMixCost`. Альтернатива побеждает только с запасом 0.1. Подробности в `debug.fullMix`. |
| P2 | `fullmix.ts`, `effectiveExit`; `planBeatmatch` | Завершённость раздела и потери финала A считаются в момент, когда A реально стихла (фейдер × полосы EQ × фильтр, −10 дБ), а не по формальному концу деки. |
| P3 | `entryCandidates`, `entrySkipCost`, `pickupLost` | `audibleStart` всегда среди кандидатов. Срезанный затакт (доля перед входом нарастает к нему) штрафуется. Пропуск начала B, такого же плотного, как основная часть песни, дорожает после 5 с; редкое вступление остаётся дешёвым. |
| P4 | `fullMixCost` | Окна по 1 с: дыра относительно линии от уровня A к уровню B, «A уже закончилась, у B ещё нет основы», скачки суммарного уровня больше 4 дБ за 0.5 с. |
| P5 | `planBeatmatch` | Неуверенный пульс (confidence < 0.55 или jitter > 20 мс): не больше 8 тактов. Для 1:2 нужен совпадающий рисунок ударных (`drumAlignment` ≥ 0.2), иначе не больше 4 тактов; рисунок не измерен — не больше 8. |
| P6 | `withBassShift`, финалисты | Передача баса остаётся по правилам `bassContinuity`. Для рендер-проверки добавлены варианты на долю раньше и позже. |
| P7 | intro-drop, echo-tail | Плотное вступление B (по сравнению с его основной частью) под плотной A: середина A отступает. Если оба плотнее своей основной части и оба голоса неизвестны — вариант отклоняется. Эхо при неизвестном голосе A: только после закрытого раздела или фразы, при редком последнем такте; хвост затихает на −40 дБ за 1.5 с. Петли без карт уже были выключены. |
| P8 | `micro-onset.ts` | Неизвестная карта больше не блокирует коррекцию, но нужно не меньше 6 согласованных бочек и разброс не больше 2 мс. Сдвигается только вход B. |
| P9 | `mir/analyze.ts`, `localFeatures` | Каждую секунду: локальная тональность (окно 8 с, тот же FFT) с уверенностью и плотность атак. Неуверенная тональность сохраняется пустой. Клэш локальных ключей ограничивает выбор и приглушает середину. |
| P10 | `engine/render-check.ts`, `AutoMixService.planChecked` | Сервер рендерит 2–5 финалистов тем же `MixerCore` на уже декодируемом PCM: K-взвешенный провал и всплеск (окно 3 с), ограничитель, дыры в басе, двойные удары. План меняется, только если выбранный явно проваливается (запас 0.3), а замена сохраняет не меньше 3/4 длины. Планирование финалистов и рендер идут шагами: после каждого плана и каждых 32768 кадров отбор уступает очередь другим запросам, чтобы встроенный сервер iPhone продолжал отдавать PCM. Без PCM план кэшируется с пометкой и проверяется при следующем запросе. |

P11 (модель детекции пения) и P12 (обучение cue/EQ) не внедрялись. Сам документ называет их условными, для них нужны модель и накопленные данные.

## Проверка

- Тесты: `npm test` — 852 из 852 (после `npm run ios:prepare`: бандл старого `apps/ios` обновлён под новую версию).
- Ядро: 392 из 392. Новый файл `packages/core/test/fullmix.test.ts` (13 тестов). Два старых теста обновлены под новое поведение: `micro-onset` (P8) и `transition-techniques` (передача баса теперь проверяется на измеренно-инструментальных треках).
- `npm run typecheck` — без ошибок.
- Сравнение: `npx tsx tools/stemless-ab.ts --tag NAME --sample 300 --render 14`. Тот же анализ из базы `data-dev`; контроль — снимок `tools/.cache/stemless-before-2026-10-22`. Новые правила меняют то, что эти числа не измеряют: целое начало B, уход A по разделу, отказ от эха и наложений над неизвестным голосом. Улучшение должно подтвердиться прослушиванием и оценками в `transition_log`. Сейчас из оценённых пар анализ версии 12 есть только у четырёх, и все четыре изменились.

## Последствия

- Смена версии анализатора: при запуске сервер в фоне заново проанализирует всю медиатеку. Кэш переходов не используется из-за новой версии планировщика.
- Каждая пара без стемов планируется 2–4 раза (альтернативы). Плюс один раз на пару — рендер финалистов длиной примерно 12 с + длина перехода.
- Не проверено: прослушивание, скорость и память на iPhone, работа P9 на настоящих анализах версии 13 (в сравнении локальных признаков ещё нет), вклад P10 в фоне iOS-сборки.
