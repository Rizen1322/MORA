# MORA 0.1.3 — порядок любимых треков

21 октября 2026.

Причина: страница «Любимое» использовала время добавления аудиофайла. Импорт шёл от начала списка к концу, поэтому старые песни скачивались позже и поднимались вверх. Параллельное скачивание также влияло на порядок; ответ `/tracks` не обязан повторять порядок запрошенных идентификаторов.

Исправления:

- Результат пакетного добавления сохраняет порядок исходных позиций, а не порядок завершения запросов. Неудачные реакции не включаются в успешный результат.
- После добавления в «Любимое» отдельный локальный запрос сохраняет порядок успешных записей, новые сверху. Он не отправляет реакции Яндексу и не меняет даты добавления аудиофайлов.
- «Любимое» сортируется по дате отметки или сохранённому порядку. Записи без этой даты используют прежнюю дату добавления. Обычный новый лайк поднимает трек вверх.
- Списки Яндекса восстанавливаются по порядку идентификаторов из списка лайков, даже если метаданные пришли в другом порядке.
- Ошибка сохранения порядка показывается пользователю, не отменяя уже добавленную музыку.

Для старых импортов порядок можно сохранить повторным выбором тех же записей и нажатием «В Любимое». Если трек уже есть в медиатеке, аудио повторно не скачивается. Уже существующие даты не пересчитываются автоматически по догадкам.

Проверка: 49 целевых тестов (пакетный импорт, сохранение порядка, полный импорт Яндекса), проверка типов, production web build и сборка установщика `MORA-Setup-0.1.3.exe` прошли. Фикстура Яндекса намеренно возвращает метаданные в обратном порядке. Сервер 4730 перезапущен с исправлениями. Полный прогон: 562/562 теста, 42 файла, 70,94 с.

Оставшиеся задачи:

1. Начало воспроизведения до окончания скачивания из публичного источника. PCM уже умеет постепенно декодироваться, но сетевой файл пока сначала скачивается полностью.
2. Полный импорт больших коллекций лайков Яндекса: текущий список источника ограничен 60 записями, отдельный маршрут лайков — 300. Нужны порционное чтение/подготовка, возобновление и честный прогресс.
3. Проверка реальных переходов на слух: особенно плотный вокал, большие различия темпа и записи без готового анализа. Вокальное разделение сейчас требует настроенного Python-компонента, в обычный установщик он не входит.
4. Независимая скорость и высота тона, реверберация; перевод текстов; Discord Rich Presence.
5. Проверка нового обновлятора через настоящее окно Electron и расширенная проверка офлайна/обновления профилей. Скачивание, контрольная сумма, пробный запуск и откат обновлятора отдельно проверены.

Приложение для iPhone остаётся отдельной разработкой; настольный yt-dlp и Python нельзя просто перенести в iOS.
