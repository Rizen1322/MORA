# MORA без аккаунтов: поиск, звук, версии, звук-панель, загрузки, импорт, тексты, радио

21 октября 2026. Основа — идеи Riff (https://github.com/rootscripts/riff, изучен `add6843dc57cc86a93a1692c8c339bba4f9099c2`, он же upstream HEAD на эту дату), переписанные под архитектуру MORA: звук любых источников идёт через наш AudioWorklet-движок и AutoMix, а не через второй HTML-плеер. Яндекс остаётся необязательным источником.

## Главный сценарий (проверен на packaged-сборке)

Чистый профиль, PATH = `C:\Windows;C:\Windows\System32` (нет Node, Python, FFmpeg, yt-dlp в системе), без аккаунтов:
поиск «Yanix Верить» → первые результаты **0,72 с** → Enter → звук через наш движок **5,2 с** (холодный профиль; в тёплом dev-прогоне 2,8 с) → следующий трек готовится заранее, переход и Next работают → предпрослушивание версии ставит основной трек на паузу и возвращает его после закрытия панели.

## Что сделано

**Провайдеры и звук** (`apps/server/src/public/`)
- `ytdlp.ts` — запуск yt-dlp: `spawn(bin, [args], { shell: false })`, фиксированные опции, `--` перед единственным URL, белый список хостов (только https YouTube/SoundCloud), таймаут, AbortSignal, лимит вывода, приоритетная очередь (звучащий трек → следующий → поиск → фон), 2 процесса максимум, классификация ошибок без URL в тексте, TLS-проверка не отключается. JS-челленджи YouTube решает собственный Electron-бинарник приложения в режиме Node (`ELECTRON_RUN_AS_NODE` только в окружении yt-dlp), отдельный Deno не нужен.
- `ytmusic.ts` — публичный поиск YouTube Music (`WEB_REMIX`) и радио `/next`: таймаут, лимит размера, circuit breaker; сохраняет **explicit-бейдж самого источника**, ID артиста и альбома.
- `provider.ts` — три понятия раздельно: `metadataSource` (где найдено: YouTube Music/YouTube/SoundCloud/импорт), `provider` (откуда звук: youtube/soundcloud), конкретная запись (`externalId` + канонический URL). Подписанные ссылки нигде не хранятся: аудио скачивается один раз в исходном формате (opus/m4a, без перекодирования), проверяется ffprobe, публикуется атомарно (staging → rename) в `data/remote/<provider>/<sha256>.<ext>`. Singleflight на запись, LRU-кэш поиска и метаданных; `prepare` не доверяет метаданным из браузера, только тому, что сервер сам выдал. Если файл вытеснен — скачивается снова; если байты другие — новый content hash, старый анализ/stems не переиспользуются.
- «Технические» строки: проигранный результат поиска создаёт трек с `saved = 0` — он играет, но не засоряет медиатеку и «Недавно добавленные». Лайк или «Сохранить в медиатеку» переводит его в коллекцию.
- AutoMix: подготовка трека отдельно от анализа — трек играет сразу (безопасный переход), анализ и планы обновляются по готовности (существующий pipeline по content hash).

**Единый поиск** (`apps/web/src/pages/Search.tsx`) — «Все / YouTube Music / YouTube / SoundCloud / Моя музыка», Яндекс отдельной ссылкой при подключении. Debounce 300 мс, отмена старых запросов (закрытие запроса отменяет работу сервера), каждый источник появляется по готовности в фиксированном порядке секций, retry только упавшего источника. Ранжирование (`match.ts`): совпадение названия/артиста, тип «песня», длительность, штраф за cover/remix/slowed/live, если их не просили; просмотры не используются. Ё/е, регистр, пунктуация, `feat/ft`. Стрелки/Enter, «Играть следующим», «В очередь», лайк, «Сохранить», «Скачать», «Радио по треку», «Найти другую версию», «Открыть в источнике». История запросов локально, с очисткой.

**«Найти другую версию»** (`components/VersionPanel.tsx`) — боковая панель (на телефоне — нижний лист), редактируемый запрос, варианты (Explicit, Без цензуры, Clean, Radio edit, Альбомная, Ремикс, Live, Slowed), выбор источников, свои файлы. Метки показывают происхождение: «E» — так указано источником, остальное — предположение по названию; отсутствие цензуры **не проверяется**. Действия: «Только сейчас» (заменяет текущую позицию очереди, без атрибуции заменённой), «Использовать для этого трека» (таблица `track_bindings`: лайки/плейлисты/история остаются на треке, а PCM/анализ/stems/планы/тексты — на выбранной записи), «Добавить отдельно», «Вернуть исходную запись». Яндексу не отправляется feedback, если фактически играет другая версия.

**Звук** (`packages/core/src/dsp/tone.ts`, `components/SoundPanel.tsx`) — 10 полос 31…16k Гц, ±12 дБ, ввод числа, двойной клик — сброс, пресеты (свои сохраняются), bypass, предусиление, **автоматический запас по измеренной суммарной кривой** (не по максимальному слайдеру), баланс, моно, выравнивание громкости, устройство вывода (`setSinkId`, иначе «как в Windows» — микрофонное разрешение не запрашивается). Порядок: DJ-микс → EQ пользователя → громкость → true-peak лимитер (после лимитера усиления нет). Тест: горячий бас-мастер + 10 дБ на басу → после лимитера **≤ −0,95 dBTP**, без NaN, без щелчков при скачке 12 дБ.

**Загрузки** (`public/downloads.ts`, `pages/Downloads.tsx`) — очередь (2 параллельно), прогресс по каждому файлу, пауза/отмена/повтор, ожидание и повтор при отсутствии сети, переживает перезапуск. Скачанное закрепляется (`pinned`) и никогда не удаляется LRU-кэшем; текущий/следующий защищены по времени использования. Предел кэша, очистка только кэша, свободное место. Битая/частичная загрузка не публикуется.

**Импорт** (`public/collections.ts`, `public/imports.ts`, `pages/Import.tsx`) — Spotify (embed-страница, полная пагинация, когда Spotify её отдаёт), Apple Music (альбомы — официальный iTunes Lookup, плейлисты — данные страницы), YouTube/SoundCloud плейлисты (yt-dlp, полная пагинация), файлы CSV/JSON/M3U. Порядок и повторы сохраняются; неполное чтение честно помечается («Spotify без входа показал первые 50…»). Сопоставление: ISRC, артист, название, теги версий, длительность; «найдено» ≥ 0,8, «проверьте» 0,55–0,8, иначе «не найдено». Предпросмотр-отчёт → плейлист; повторное нажатие обновляет тот же плейлист; ненайденные позиции остаются в отчёте со своим местом и встают на него после ручного выбора. Звук импортированных треков скачивается при первом прослушивании.

**Тексты** (`apps/server/src/lyrics.ts`, `components/LyricsPanel.tsx`) — LRCLIB (точный запрос с длительностью, затем поиск с проверкой артиста/названия/±4 с), `.lrc/.txt` рядом с файлом, кэш по записи, «нет текста» ≠ «нет сети», подсветка строки, клик — перемотка, сдвиг ±0,25 с с сохранением для записи, ручная прокрутка не сбрасывается. В AutoMix эти тайминги не используются.

**Радио без аккаунта** (`lib/radio.ts`, `lib/radio-taste.ts`) доступно на главной, в «Моей волне» и в меню трека. Персональная станция объединяет рекомендации YouTube Music от нескольких любимых исполнителей, учитывает лайки и историю, исключает дизлайки и недавние повторы между источниками. При остатке меньше 10 кандидатов заранее запрашивает новую порцию. Настройки: знакомое/открытия, энергия и «Для микса». Энергия, BPM и тональность влияют только при наличии анализа; неизвестные значения не угадываются. Это рекомендации сервиса с локальным ранжированием, без отдельного обученного рекомендательного сервера.

**Удобства** — таймер сна (15/30/60 мин, своё время, конец трека — с затуханием от начала AutoMix-перехода, конец очереди; по настенным часам — сон/пробуждение учитываются; сохранённая громкость не меняется); компактное окно 420×176 поверх других (то же окно, один движок), восстановление размеров; панели «Звук/Текст/Очередь» в одной колонке, взаимоисключающие; media keys работают и в трее (`globalShortcut`, т.к. Electron не публикует Web Audio в SMTC; повторный захват, если клавиши заняты другим плеером).

## Ограничения (честно)

- Звук **не прослушивался**: проверены движок, PCM, underruns, true peak в тестах.
- YouTube/SoundCloud — неофициально; условия сервисов ограничивают скачивание; часть записей может требовать вход или быть недоступна в стране — показывается причина. SoundCloud-поиск медленный (6 с).
- Плейлисты Spotify без входа могут отдаваться не полностью (проверено: «Today's Top Hits» — 50 треков без общего числа; отчёт это показывает). Альбомы Spotify и плейлисты YouTube читаются полностью.
- В 0.2.0 добавлены ранний старт для потоковых контейнеров, полный возобновляемый импорт лайков Яндекса, реверберация и текст внутри полного плеера. M4A/MP4 пока ждут завершения скачивания. Подробности и границы проверки — [отчёт 0.2.0](mora-audit-0.2.0.md).
- В 0.3.0 добавлены независимые скорость/тон и автономный CPU-комплект вокального разделения, включая YouTube/SoundCloud. [Проверка 0.3.0](mora-audit-0.3.0.md). Перевод и Discord исключены из текущей задачи пользователем; saturation и обрезка аудио не реализованы.
- В настольной версии 0.1.2 доступно обновление yt-dlp через настройки: официальный stable-релиз, SHA-256, пробный запуск, переключение при следующем запуске и откат. [Проверка 0.1.2](mora-audit-0.1.2.md).
- Экспорт и восстановление плейлистов добавлены в 0.1.1: JSON со списками и источниками, без аудиофайлов и подключений аккаунтов. Подробности повторной проверки — [mora-audit-0.1.1.md](mora-audit-0.1.1.md). Таблица выше относится к исходной проверке 0.1.0.
- Радио берёт «up next» YouTube Music; без сети онлайн-подбор не работает (скачанное играет).
- Переход между двумя технически только что скачанными треками до готовности анализа — безопасный кроссфейд, beatmatch появляется после анализа.

## Следующему разработчику

- Сборка: подготовить FFmpeg и yt-dlp соответствующими скриптами, затем `node apps/desktop/scripts/fetch-vocals.mjs --python <Python 3.12>` и `npm run desktop:package`. Python нужен машине сборки; слушатель получает зависимости внутри приложения.
- Браузерный режим: сервер сам найдёт `apps/desktop/vendor/yt-dlp` или `yt-dlp` в PATH (`YTDLP_PATH`), JS-runtime — текущий Node.
- Приоритеты: оценка сохранённых примеров на слух, качество сложного вокала; возможное ускорение SoundCloud и ранний старт M4A/MP4. Обновление yt-dlp, ранний старт последовательных контейнеров, скорость/тон и автономный вокальный комплект реализованы, см. отчёты 0.1.2–0.3.0.
