# Выравнивание тактов по рисунку ударных, 20 октября 2026

`am-analyzer-9`, `am-planner-v5-drums-1`. Beatmatch, длина сведений, выбор выхода/входа,
передача голоса и микшер не переписаны: меняется только фаза такта уже выбранного входа B.

## Откуда задача

Реальные оценки слушателя в `transition_log` (`data-dev/automix.sqlite`): из последних
оценок две — «сбился ритм» на beatmatch_blend (`am-planner-v3-phrases-2`):
«1ST DAY SMOKE → Panic Attacks» (#443) и «Бассок → BOMB» (#438), ещё две такие же у v2-5.

Проверка на исходниках (`tools/bar-profile.ts`) показала: доли совпадают, а такты — нет.
У A малый барабан стоит на позиции 2 найденного такта, у B на позиции 2 минимум:
бочка одного трека попадает на малый другого. Найденная сильная доля строилась по смене
гармонии и низкой полосе по всей песне; у части треков уверенность была 0,06–0,36.

## Изменение

- Анализатор сохраняет для каждой доли глобальной сетки и каждого локального региона
  `accents.kick` (подъём огибающей < 150 Гц) и `accents.snare` (1–4 кГц: малый, клэп;
  хэты в основном выше), делённые на медиану по сетке. Линейная огибающая 10 мс, а не
  логарифмический onset: громкий малый весит больше 3-мс щелчка бочки. Это энергии полос,
  а не распознавание инструментов. Размер ~2 числа на долю.
- Планировщик после выбора лучшего кандидата beatmatch (relation 1) строит профиль такта
  (средний акцент на позициях 0..3) для A и B строго на участке наложения и считает
  корреляцию Пирсона A с B, повёрнутым на k = 0..3 доли. Полосы без рисунка
  (СКО/среднее < 0,3: ровная бочка «на каждую долю», плоские хэты) не участвуют.
- Если k ≠ 0 лучше текущей фазы минимум на 0,5 и сам ≥ 0,3, вход B переносится на
  +k или −(4−k) долей (одинаковое выравнивание). Выбирается вариант с меньшим измеренным
  голосом B в наложении, затем меньший сдвиг. Режим preserve не пропускает начало;
  локальный регион и конец трека соблюдаются. Длина, выход A и область входа не меняются.
- `debug.drumPattern = { match, k, blocked? }`, причина в `reasons`, `phraseAligned=false`
  при сдвиге. Повторный поиск при потере голоса B (`vocalRepair`) принимает сохранённый
  вход на любой доле B.

Первая версия сравнивала кандидатов уже со сдвигом и с окнами шире наложения. Проверка
по рендеру это опровергла: при почти равных оценках выигрывали короткие 7-секундные
сведения вместо 28-секундных, а рисунок куплета после наложения ломал уже совпавшие пары.
Обе ошибки исправлены до финальных цифр.

## Проверка

Автоматические измерения, не прослушивание.

- `npm test`: 424/424, 23 файла (`packages/core/test/drum-alignment.test.ts`: поворот
  рисунка, сдвиг на долю с бочкой на бочке, неизменность совпавших пар и планов без
  accents, preserve, accents на синтетическом хип-хопе, отсутствие рисунка у house).
  `npm run typecheck`, `npm run build` — exit 0.
- Те же 24 трека / 552 пары / settings, что в v4 (`user-library-mixed-v5-drums-plans.json`):
  методы не изменились (437 crossfade, 115 beatmatch), средняя длина 11,26 с та же.
  Рисунок измерен у 58 beatmatch, сдвиг в 30. Максимум скрытого голоса B 5,516 → 4,829 с;
  средние maskedA 0,356 → 0,360, maskedB 0,697 → 0,695.
- Сквозная проверка по рендеру (`tools/drum-ab.ts`): каждая дека рендерится отдельно
  тем же микшером (tempo maps, WSOLA), акценты обеих сэмплируются на долях A в выходном
  времени. Из 30 сдвинутых пар измеримы 24: совпадение при фактическом выравнивании
  лучше в 20, нейтрально в 2, хуже в 2 («STORM II → Благословлён», «Зависима → Беспечный
  рыцарь тьмы» — расходятся сетка анализа B и рендер). 60/60 рендеров завершены,
  0 underrun, пик ≤ −1,05 dBFS. В сдвинутых парах maskedA 0,567 → 0,644 с, maskedB
  1,143 → 1,113 с.
- Пары из жалоб (совпадение в рендере при k=0, до → после): #438 −0,58 → 0,94;
  #353 0,18 → 0,43; #364 −0,96 → −0,20 (частично: анализ выбрал k=3, рендер показывает k=2).
  #443 не сдвигается: на участке наложения запас 0,44 < 0,5, хотя рендер тоже указывает
  на k=3. Хорошо оценённая #378 не изменилась. #396 и #393 («сбился ритм») рисунком
  не объясняются и не меняются.
- Повтор аудита v4 (`user-library-mixed-v5-review.json`, 8 рендеров): метрики совпадают
  с v4 (в выборке нет сдвинутых пар). Сервер на 4731: анализ в worker даёт `am-analyzer-9`
  с accents, `/api/automix/plan` для «Бассок → BOMB» возвращает сдвиг k=1.

A/B-файлы для прослушивания: `data-dev/reports/previews/drum-ab-rated/` и

## Ограничения

- Только 4/4 и relation 1; half/double-time пары не сравниваются.
- Порог 0,5/0,3 и контраст 0,3 подобраны на тех же оценках (мало данных, ~16 beatmatch
  с оценкой); это гипотеза, пока слушатель не подтвердит.
- Сдвиг не исправляет ошибку сетки на пол-доли и дрейф темпа.
- После перезапуска сервер переанализирует медиатеку (`am-analyzer-9`, ~2 с на трек
  в фоне); до этого для непроанализированных треков действуют запасные переходы.
