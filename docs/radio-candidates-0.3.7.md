# Расширение кандидатов онлайн-радио

22 октября 2026. Действующий локальный taste-ranker, дизлайки, история, ограничение повторов исполнителей и режим подбора под микс сохранены. Добавлены пути получения кандидатов, а не другой плеер или удалённый вычислительный сервер.

- Сначала настоящий YouTube Music up-next. Когда в нём меньше 12 записей, дополнительно запрашивается обычный YouTube Mix через отдельный WEB client и `www.youtube.com`; ошибка Music `/next` не блокирует его circuit breaker. YouTube-кандидаты отмечаются как видео из YouTube.
- Только если оба пула пусты и сервер знает исходный трек, можно использовать публичные Deezer artist-radio metadata. Поиск исполнителя требует точного Unicode-совпадения имени, включая кириллицу. Отбирается не более трёх записей; аудио ищется нашим существующим resolver. Принимается только совпадение названия и артиста с разницей длительности не более восьми секунд и confidence ≥0,9. Другие результаты пропускаются. Deezer не используется как источник аудио.
- Не более двух metadata-match поисков одновременно, три суммарно. Общий deadline всех путей — 14 секунд. Уже полученный пригодный пул остаётся доступен, даже если дополнительный источник не успел. Неудачи не кэшируются; успешные пулы ограничены 64 записями кэша на пять минут.
- Одновременные запросы одного пула объединяются с независимой отменой каждого потребителя. Смена станции и уход в другой контекст воспроизведения отменяют ненужные запросы старой станции. Удаление upcoming продолжает использовать прежнюю модель ownership/refill.

## Проверка

26 targeted tests, три файла: `radio-candidates.test.ts`, `radio-session.test.ts`, `radio-taste.test.ts`; серверный TypeScript без ошибок. Проверены отказ каждого YouTube пути, повтор после отказа, дедупликация, deadlines, сохранение частичного успеха, индивидуальная и полная отмена, нежелательные/live/слишком длинные видеозаписи, строгий metadata match, лимит трёх запросов, отказ от другого одноимённого результата, реакции/recency/mix-ranking и смена ownership станции.

Одиночные live smoke на этой сети, не сравнительный benchmark и не p95:

| Проверка | Результат |
| --- | --- |
| Обычный YouTube Mix по OneRepublic — Counting Stars | 25 записей, 669 мс |
| Общий путь с доступным Music up-next | 49 записей, 693 мс |
| Deezer search artist / artist radio, без аккаунта | HTTP 200, 320 / 144 мс |
| Принудительно пустые оба YouTube `/next`, реальные Deezer metadata и реальные Music search | 2188 мс, три ограниченных поиска, одна уверенно сопоставленная запись: OneRepublic — Love Runs Out, 225 с |

Последняя проверка подменяла только ответы `/next` в отдельном временном Node-процессе; пользовательская очередь и работающий сервер не менялись. Неуверенные совпадения в этой проверке не добавлялись.

## Первичные источники и границы

Форма обычного YouTube Mix сверена с [экстрактором YouTube yt-dlp](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/youtube/_tab.py) и реальным ответом WEB `/next`. Это внутренний web endpoint YouTube, а не обещанная стабильная публичная Data API. Публичный [playlistItems.list](https://developers.google.com/youtube/data/reference/rest/v3/playlistItems/list) — другой API и не основание обещать поддержку персонального Mix без ключа.

[Deezer Developer API](https://developers.deezer.com/api) на дату проверки перенаправлял документацию на вход; доступность ограниченных metadata endpoints проверена отдельными реальными запросами. Из этого не следует гарантированная доступность сервиса во всех сетях. Ни cookie браузера, ни авторизация, ни отключение TLS-проверки не добавлены.

Качество рекомендаций на длинных пользовательских сессиях, p95 в сети друга и субъективное прослушивание не проверялись. Повторяющиеся metadata-имена исполнителей без стабильного ID нельзя различить абсолютно; точное имя снижает риск, а metadata audio-match дополнительно требует название и длительность.
