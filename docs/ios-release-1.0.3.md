# MORA iOS 1.0.3 (build 4), 24.10.2026

## Нагрев и батарея

- OPFS: `flush()` только после записи; раньше каждое чтение куска PCM во время игры сбрасывало файл на диск.
- Анализ получает каналы L/R напрямую: без лишнего чередования (~85 МБ и два прохода по сэмплам на трек).
- Кэш PCM — 16 бит с запасом 6 дБ над полной шкалой: вдвое меньше записи на флеш, `read()` по-прежнему отдаёт float.
- Заблокированный экран: React не перерисовывает невидимый интерфейс от часов; движок шлёт 4 тика в секунду вместо 20.
- База sql.js переписывается раз в 60 с (было 30), позиция — раз в 30 с (было 5) и при уходе в фон.
- После 3 минут паузы AudioContext засыпает (раньше свёрнутое приложение на паузе «играло тишину» и не давало iOS усыпить себя).

## Новое

- Воспроизведение во время загрузки для HLS ADTS/MP3 (YouTube, SoundCloud): звук после первых ~256 КБ, затем продолжение с того же сэмпла по полному файлу.
- Токены провайдеров шифруются AES-256-GCM ключом из Keychain (только это устройство, после первой разблокировки).
- «Послушать переход» в очереди: сервер рендерит запланированный AutoMix-переход в WAV.
- Автопродолжение радио после конца очереди, возврат к онлайн-подбору после появления сети, «Похожее на этот трек», «Радио по исполнителю», «Лайкнуть все».
- Скачивание лайкнутых онлайн-треков для офлайна (настройка), вкладка «Любимое» в нижней панели, новый вид настроек, источников и диагностики.
- Оценки переходов мягко влияют на выбор плана для похожих пар.
