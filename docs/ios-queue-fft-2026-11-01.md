# iOS 1.0.21 (22): сохранение очереди и нативные вычисления MIR

Продолжение исправлений после двух пользовательских журналов 1.0.19 и 1.0.20. Rust на iOS не подключается, записи воспроизводятся целиком.

## Очередь

Повторный короткий manifest сохраняет совпадающий ещё не декодированный хвост прежнего manifest. Намеренное редактирование страницы передаёт replaceFuture=true; обычное обновление его не передаёт. Для этого используется отдельный nativeQueueEditRevision: общий queueRevision не меняется, поскольку им пользуется загрузчик длинных каталогов.

Сопоставление выполняется по entryId+trackId. Числовые нативные индексы после пропуска повреждённого источника расходятся с исходным списком, поэтому для пустого обновления используется entryId реально звучащего трека. Явная очистка и repeat-one не восстанавливают удалённый хвост. Сохранённые источники освобождаются при stop/fail.

## Анализ

В журнале 1.0.20 feedingPcm занял49.289с, spectrum90.052с до отмены. feedingPcm включает фильтры и накопление признаков, а не только передачу PCM. Полная замена base64 не решала этот этап.

FFT перенесён в Swift: тот же radix-2 алгоритм и Double-арифметика, вызов один раз на преобразование. Копии typed arrays создаются до следующих вызовов JSC; временные backing-store указатели не удерживаются между вызовами. Существующая JS-реализация сохраняется для других платформ и неподходящих размеров буфера.

Два потока децимации теперь также используют Swift: один вызов на блок, те же31 коэффициент, история и фаза. Выход сохраняется в Double, а JS-callback выполняется локально после возврата блока. Измерение громкости и последующие алгоритмы MIR остаются в JS.

## Проверка

Агент gpt-6-astra с reasoning low независимо проверил связанные вызовы, исправил намеренную очистку очереди, гонку редактирования при handoff и контракт размера FFT. Дополнительно исправлены случай пропущенного источника и восстановление владельца трека после приостановки WebContent.

В тестах проверяются сохранение74-го элемента после короткого обновления, явная замена, пустой prefix, пропущенный источник, восемь треков в фоне без WebView, семь резервных кроссфейдов при заблокированном анализе, комплексный FFT против DFT, subarray/границы/типы и полный анализ180-секундной синтетической записи против Node. Длинный macOS тест компилируется с -O. Его время не является измерением на iPhone.

Бесконечный подбор новых рекомендаций «Волны» всё ещё зависит от WebContent. Исправление сохраняет уже переданный большой список и не подменяет нативную реализацию подбора рекомендаций.

Дополнительные проверки агента: чередование native/fallback на блоках0/1/2/7/31/4/127/65536/1, Float64-выход, история/фаза, невалидный вход без изменения истории. Тесты subarray обнаружили ошибку: JSObjectGetTypedArrayBytesPtr возвращает базу backing buffer. Все обращения к существующим представлениям теперь учитывают JSObjectGetTypedArrayByteOffset, полученный до временного указателя. Новые массивы имеют нулевое смещение. Источник поведения API: https://raw.githubusercontent.com/WebKit/WebKit/main/Source/JavaScriptCore/API/JSTypedArray.cpp

Локально после iOS-исправлений:1151 тест в147 файлах, typecheck всех workspace прошёл. Нативная проверка не подменяется этим локальным результатом.
