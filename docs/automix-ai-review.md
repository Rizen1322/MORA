# Предложения внешнего ИИ: проверка и локальный план

21 октября 2026. Требование пользователя: сначала ПК; вычисления на устройстве, без покупного/внешнего сервера обработки. Локальный backend desktop-приложения остаётся частью приложения. Перечень предложений — материал для инженерной проверки, не описание уже готовых функций.

## Реализовано в 0.3.2

**Настоящий фильтр деки.** Добавлен stereo TPT state-variable HPF/LPF и lane `filter`: −1 LPF, 0 точный bypass, +1 HPF. Плавное управление за 20 ms, пересчёт коэффициентов раз в 16 сэмплов, без выделений памяти в обработке, без резонансного усиления. Подключён к washout-переходам при разрешённом EQ handoff. Это дополняет существующий обмен полосами, а не переименовывает его. Работает в AudioWorklet и том же offline MixerCore. Версия планировщика `am-planner-v8-sweep-1`.

Использование LP/HP-фильтров в переходах описано в [официальном руководстве Traktor](https://docs.native-instruments.com/ni-tech-manuals/traktor-pro-manual/en/effect-reference) и [уроке Native Instruments](https://blog.native-instruments.com/dj-transitions/). Конкретный TPT-код и условия выбора MORA собственные; идентичность алгоритму Apple не заявляется.

**Порядок плейлиста под микс.** «Собрать микс» предлагает плавный порядок или нарастание энергии по измеренным BPM, Camelot и энергии, учитывает недавних исполнителей. Worker не блокирует UI; поиск ограничен 96 кандидатами на шаг. Первая запись, повторы и все позиции сохраняются; неизвестный анализ не выдумывается. Можно слушать или сохранить отдельную копию. Это эвристический set ordering, не глобальный оптимум всех переходов и не обучение на предпочтениях.

**Проверка реальным рендером.** Обновлён локальный инструмент `tools/check-playback-release.ts`: девять рендеров реальных треков в обычном режиме, 1,2× и +3 полутона; отдельно нагрузка двух дек с фильтрами. Это release-проверка, ещё не online render-in-the-loop ранжирование кандидатов.

## Обновление 0.3.5

Готовы осторожные односторонние режимы, master-deck tempo для измеренного вокала при небольшой разнице BPM и фильтровая DJ-подводка с эхом к измеренному вступлению. Поиск вокальной паузы ускорен без сокращения набора кандидатов. Подробные условия, ограниченное покрытие реальных треков и проверки — в [отчёте ПК 0.3.5](pc-release-0.3.5.md). Следующий этап — проверка и перенос на iOS, без внешнего сервера. Оставшиеся творческие эксперименты ниже не объявляются готовыми и не блокируют начало iOS.

## Разбор всех 24 предложений

| № | Предложение | Решение / фактический статус |
| --- | --- | --- |
| 1 | Loop bridge | В 0.3.4 готова конечная source loop и автоматическое удержание измеренного инструментального финала; см. `loop-bridge-0.3.4.md`. Изменение длительности A и более широкий вокальный loop-routing ещё не реализованы. |
| 2 | Filter lane | Реализовано и проверено на 32/44,1/48/96 kHz. Резонанс исключён из первой версии ради предсказуемого уровня. |
| 3 | Voice / bed | Текущее вычитание отделённого вокала уже существует. Отдельный routing bed/voice для всех эффектов ещё требует контракта и рендеров остаточного вокала. |
| 4 | Односторонние stems | В 0.3.5: только A — маска в ранней измеренной паузе до заметного входа B; только B — плавный уход всей A до измеренного голоса B. Нет маски неизвестного входящего вокала и обещания изоляции неизвестной A. Ненадёжные случаи сохраняют прежний план. |
| 5 | Master deck tempo | В 0.3.5: A остаётся в родном темпе, B синхронизируется и возвращается к своему после сведения. Только небольшой сдвиг до 3%, надёжные глобальные сетки и измеренный вокальный контекст; иначе прежняя стратегия. |
| 6 | Микрофаза | Не добавлено: локальный поиск onset/корреляции в worker, ограниченный сдвиг и обязательная уверенность; иначе исходная сетка. Нельзя двигать вход после того, как пошёл слышимый вокал. |
| 7 | Структура / features | Структура и локальная сетка уже используются. Дальнейшее расширение скоринга отдельно сравнить с текущими золотыми рендерами; не повышать долю поздних входов за счёт пропуска слов. |
| 8 | Render in loop | Offline-инструмент есть. Авторанжирование ещё не включено: 2–3 коротких кандидата в worker при запасе CPU, отмена устаревших запросов, кэш по версиям, fallback по дедлайну. |
| 9 | Momentary LUFS riding | Метр loudness/true peak существует; planner использует приближение мощности. Динамический per-deck riding не добавлен: требует проверки pumping и максимальной скорости gain. |
| 10 | Bass mono / width | Пока отсутствует на уровне дек; проверять корреляцию, сохранение энергии и плавное возвращение стерео. |
| 11 | Четыре стема | Не включать повсеместно. Опциональный локальный анализ по запросу, квоты и отмена обязательны. Автоматическая обработка всей медиатеки противоречит задаче оптимизации. |
| 12 | Key shift | Общая скорость/высота тона уже есть. Независимая гармоническая коррекция одной деки ещё не реализована; не путать эти функции. |
| 13 | Double drop | Отдельная будущая техника с надёжными drop/downbeat и отсутствием конфликта голосов. Не просто одновременное включение двух громких мест. |
| 14 | Breakdown tempo | Только по надёжно измеренному спокойному участку; отдельные рендеры, отказ при слабой уверенности. Пока не добавлено. |
| 15 | Echo freeze / ping-pong | Существуют echo-out и отдельное эхо вокала. Freeze/ping-pong не добавлены; нужны лимит feedback/длины и очистка хвоста при skip/stop. |
| 16 | Tape stop / spinback | Пока отсутствуют. Опциональные редкие эффекты с ограниченным gain, не дефолт на любых треках. |
| 17 | Riser / impact | Пока отсутствуют. Дополнительные звуки и их лицензии/уровень не должны появляться без понятной настройки. |
| 18 | Half-time | Отношение BPM 0,5/1/2 уже учитывается. Это не проигрывание записи вдвое медленнее и не доказательство совместимости барабанного рисунка. |
| 19 | Call and response | Пока не добавлено: только с надёжными границами фраз обеих записей и ограничением разрезания слов. |
| 20 | Ambient dissolve | Есть плавный fallback. Специальная текстурная техника требует распознавания слабого ритма и ограничения хвоста; пока не заявлена отдельной готовой техникой. |
| 21 | Set planner | Первая версия локального порядка готова. Глобальная оценка настоящих планов и разнообразие приёмов — дальнейший этап. |
| 22 | Обучение по рейтингам | Не добавлено. Сначала локальный журнал отказов/рейтингов и A/B; никакой отправки истории на внешнее обучение. |
| 23 | Preview / A-B / редактор | Имеющееся превью не равно полному редактору. Отдельный редактор cue/loop/фильтра ещё не реализован. |
| 24 | Серверный pre-render | Внешний сервер исключён требованием пользователя. Возможен только отменяемый короткий локальный рендер при наличии ресурса, без задержки обычного старта. |

## Дальнейшие эксперименты после базы ПК

1. Первая конечная инструментальная петля готова в 0.3.4. Следующее расширение: музыкальное увеличение хвоста и виртуальный EOF, после отдельной проверки вокальных карт и потерянного материала.
2. Независимое voice/bed routing и микрофаза. Осторожный односторонний режим и master-deck траектории уже есть в 0.3.5.
3. Короткие локальные рендеры кандидатов с дедлайном и бюджетом памяти; рейтинг по пикам, провалам уровня, onset и голосовым конфликтам, а не по громкости одного кандидата.
4. Новые творческие приёмы только после предыдущих технических проверок и прослушивания человеком.

Не подтверждены цифры эффективности, приведённые внешним ИИ. Не заявлено «как Apple» или идеальное сведение любых записей. Перед переносом DSP на iOS нужно включить новый фильтр и его state/reset в native parity-проверки.
