## Автоматические проверки

- `npm test`: **162/162**, девять тестовых файлов. Анализ и планирование, DSP/две деки, рекомендации, backend end-to-end, ручной Next и гонки контроллера.
- `npm run typecheck`: успешно для core, server и web.
- `npm run build`: успешная production-сборка с отдельным AudioWorklet.
- `npm start`: рабочий сервер на 4730, существующие 16 треков в `data-dev` доступны; пять из них — загруженные пользователем записи.
- В предыдущем проходе проверен `npm run dev`: Vite 5173 и изолированный backend 4737; `/api/health` через proxy вернул planner7 и пустую тестовую медиатеку. Проверка подтверждает исправление dev-proxy; для planner9 этот сценарий повторно не запускался.

Регрессии проверяют: структурный вход в диапазоне 20–30 с, сохранение начала и ограничение пропуска, half/double tempo, общий промежуточный BPM, предел растяжения обеих дек, интегралы карт темпа и восстановление скорости B после перехода, синкопы и смену BPM внутри записи, тишину/нечисловой PCM/короткие файлы, противофазное стерео, эхо после тихих блоков, точный trigger/gap/swap, pause/skip/seek, долгий переход с подкачкой PCM, отмену старой подготовки и обновление анализа. Контроллер сохраняет команду пользователя во время восстановления очереди при запуске.

Для ручного Next проверены музыкальный первый переход, повторное быстрое переключение, отдельная загрузка PCM после смены входа B, устаревшие HTTP-ответы и подготовка очереди. Сервер отклоняет некорректные ID/позиции с кодом 400, сохраняет `mixOnNext=false`, добавляет `true` к старым настройкам. Ограничения провайдера запрещают наложение, изменение темпа, EQ, echo и нормализацию также при ручном переключении.

Отдельный PCM-тест 120 → 132 BPM измеряет центры энергии 22 последовательных ударов после WSOLA: медиана ошибки <8 мс, p95 <15 мс, максимум <20 мс. Это допуски теста на известном сигнале, не обещание такой точности для произвольной музыки.

## Матрица аудио

Команда: `npm run eval:transitions -- --json docs/validation-matrix.json`.

Пересчитано для `am-planner-12`. Все упорядоченные пары 11 синтетических музыкальных файлов из `examples/library`, без пары файла с самим собой. Отчёт: validation-matrix.json.

| Промежуточный BPM (`tempo_bridge`) | 12 |
| Echo handoff | 36 |

| Максимальное обрезание финала A | 21,0 с |
| Входов B после 15-й секунды | 13 |

Громкость измеряется трёхсекундным K-weighted окном; временные индексы учитывают длину окна. Пропущенный финал считается по интегралу tempoA. Данные лимитера берутся из реального рендера, а не из заглушки.

Echo может закончить исходную ритм-секцию до тихого затухающего финала: этим объясняется максимальный пропущенный хвост 21 с. Это осознанная смена музыкальной точки, а не потеря PCM из-за недогрузки. Среднее снижение на синтетической матрице было −1,42, затем −1,64 (planner9), сейчас −1,44 LU; улучшение каждой пары не утверждается. У синтетических треков нет вокальных партий, поэтому новая передача голоса на них не проверяется. Метрика включает собственную динамику фрагментов и не является изолированной оценкой микшера.

Синтетические примеры предыдущего прохода: examples/transitions/README.md. Пример `09-crossfade.mp3` переходит с ambient на hiphop с входом B на **21,82 с**; JSON-план находится рядом. Все исходники этих примеров синтезированы проектом. Они не являются рендерами пользовательских записей или подтверждением последней версии каждой стратегии.

## Загруженная медиатека

Проверены **все 20 направленных пар пяти пользовательских треков** и отдельно 20 ручных переходов с середины записи. Полное сравнение и воспроизведение: [real-library-validation.md](real-library-validation.md).

Автоматические переходы: 4 сведения по битам, 2 через общий BPM, 8 echo и 6 кроссфейдов. Все 12 пар между четырьмя ритмическими треками получают beatmatch/tempo bridge/echo; раньше семь из них получали обычный кроссфейд. У FATHER восстановлена устойчивая сетка 117,99 BPM. Оркестровой Mother is the First Other искусственный постоянный бит не назначается.

На этой медиатеке среднее измеренное снижение уменьшилось с −2,42 до −1,00 LU, наибольшее — с −8,14 до −3,28 LU. Максимальное повышение выросло с +1,17 до +3,96 LU у CHILL → «Камнем вниз»; этот уровень требует субъективной проверки. Все 40 финальных рендеров завершились, без underrun и нечисловых сэмплов, sample peak не выше −1,00 dBFS с погрешностью округления.

## Браузер

В текущем проходе браузер действительно выполнил автоматический «Камнем вниз» → FATHER через `tempo_bridge`: выход A 226,296 с, вход B 1,783 с, общий темп 128,543 BPM, длительность 9,256 с. Запуск не был принудительным или запоздалым (`forced=false`, `late=false`). Также проверены первый Next FATHER → CHILL с echo-переходом 8 с и повторный Next, быстро завершающий переход. После проверки воспроизведение поставлено на паузу.

Текущая production-сборка проверена на **1440×900** и **390×844**. У основного экрана, сетки диагностики и карточки перехода `scrollWidth == clientWidth`: desktop 1169 / 1105 / 676 px, mobile 375 / 343 / 343 px соответственно. Новое отображение общего BPM и завершённого перехода помещается в оба размера. Снимки: [реальный переход desktop](screenshots/real-library-bridge-desktop.png), реальный переход mobile. После финальной перезагрузки console error/warn: **[]**. Размер viewport восстановлен.

В предыдущем проходе проверены настройки умного входа, сохранение smart/preserve, полноэкранный плеер, воспроизведение/перемотка/продолжение, waveform и переход между синтетическими треками на 1440×900 и 390×844. На телефоне отдельно прокручивалась широкая диагностическая волна. Эти отдельные сценарии относятся к предыдущему проходу; они не объявляются повторно выполненными только на основании новых снимков.

Снимки предыдущего прохода: [настройки desktop](screenshots/settings-desktop.png), плеер mobile, структурный вход mobile. Музыка и планы восстанавливаются из существующей медиатеки; новый анализ имеет отдельную версию, предыдущие записи не стираются.

## Граница проверки

Звук не прослушан моделью. Проверены численные PCM-рендеры и поведение интерфейса; MP3-примеры доступны только для синтетической музыки. Пользовательские исходники не добавлялись в `examples` и не отправлялись внешним сервисам. В том проходе разделения голоса не было; сейчас оно есть (локальный Demucs, см. [dj-automix.md](dj-automix.md)), но семантического детектора припева или слов нет. Проверка пяти записей не доказывает качество на всех жанрах или всех записях с меняющимся темпом. Аккаунты внешних сервисов не подключались.
