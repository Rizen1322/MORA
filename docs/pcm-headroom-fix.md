# Перегруз громких треков до нормализации — 20 октября 2026

Жалоба пользователя: громкий трек будто упирается в потолок и хрипит.
Найдена воспроизводимая причина в тракте приложения: `PcmCache` декодировал
оригинал сразу в s16le. Пики MP3/ресемплера выше ±1 обрезались до передачи
в микшер. Последующая нормализация, громкость и true-peak limiter могли лишь
сделать уже повреждённый сигнал тише. Офлайн-аудитор использовал float и потому
сам по себе не ловил эту разницу между аудитом и реальным HTTP-воспроизведением.

## Исправление

- Серверный оригинальный PCM-кэш теперь stereo f32le, 8 байт на кадр, `.f32`.
  Старые `.s16` не переиспользуются: новый кэш декодируется из исходника.
- Старые файлы сохраняются до вытеснения и учитываются в прежнем дисковом бюджете;
  pinned записи защищены. Нейросетевые stems не менялись.
- `/api/tracks/:id/pcm?...&format=f32le` отдаёт float с `X-PCM-Format: f32le`.
  Отсутствие параметра сохраняет s16le-контракт для старых клиентов.
- Новый плеер запрашивает float и распаковывает его без деления на 32768.
  Поддержка ответа старого сервера остаётся по заголовку/legacy fallback.
- Данные могут превышать единицу до нормализации и финального лимитера;
  на выход напрямую они не отправляются. Потолок/настройки лимитера не повышались.
- Float-кэш и сеть требуют вдвое больше байтов на кадр, чем прежний s16.
  Лимит кэша остаётся в байтах, так что вместимость по минутам уменьшается.

## Проверки

Новые `apps/server/test/pcm-headroom.test.ts`:
чистый float-WAV с амплитудой 1,25 проходит серверный API без срезания;
точное совпадение с независимым ffmpeg-декодированием на 44,1/48 kHz при seek;
старый s16-контракт, неверный формат, отказ от старого срезанного кэша,
повторная загрузка `.f32` и правильные totalFrames/EOF.

Новый тест контроллера проверяет передачу +1,25 и −1,125 в AudioWorklet без
обрезания и ошибочного масштаба. Это не проверка физических динамиков.

Реальные исходники из фиксированной пользовательской выборки, полный decode
на 48 kHz; проверенные HTTP-фрагменты точно совпали с float-оригиналом:

| Трек | Peak dBFS | Сэмплов вне диапазона s16 |
| --- | ---: | ---: |
| FATHER | +0,662 | 14 308 |
| На Крышах | +1,647 | 3 692 |
| STORM II | +0,793 | 1 297 |

Диагностический скрипт: `tools/.cache/check-real-headroom.ts` (локальный, читает
существующие оригиналы/SQLite без изменения аккаунта).
`npm run typecheck` и `npm run build` прошли.
В первом общем прогоне: 426/427, один сбой ожидания состояния фоновой очереди
в `stems.test.ts`; отдельный повтор этого файла — 40/40. Финальный общий отчёт:
`tools/.cache/headroom-tests-final.json`: **427/427 тестов, 24 файла**,
полный повтор с `--maxWorkers=2`, exit 0. Сервер отдаёт новую production-сборку,
HTTP-проверка на реальных треках выполнена после перезапуска.

Сервер перезапущен с новым кодом. Старую открытую страницу нужно обновить,
чтобы она начала запрашивать float. Исходные MP3 и пользовательские настройки
не изменены. Уже записанный в сам исходник перегруз эта правка не восстанавливает;
субъективное исчезновение жалобы нужно подтвердить прослушиванием пользователем.
