## Почему росла MORA

В установленном профиле `C:/Users/Rizen/AppData/Local/MORA/data` было более 3 GB. Размер включает исходное аудио, декодированный PCM и выделенный вокал. Раньше импорт автоматически ставил разделение вокала всей медиатеки в очередь; готовые стемы библиотечных записей фактически не вытеснялись по лимиту.

Исправлено в 0.3.2:

- Разделение новых записей по запросу текущего/следующего трека, вместо всей библиотеки при запуске и импорте.
- PCM по умолчанию 512 MiB (`PCM_CACHE_MB`), вокальные стемы 1024 MiB (`STEMS_CACHE_MB`), исходное сетевое аудио 512 MiB. Явно сохранённые настройки пользователя сохраняются.
- PCM очищается после подготовки и периодически. Стемы вытесняются по использованию, включая холодные записи библиотеки. Текущие/следующие треки, активные поколения стемов и закреплённое офлайн-аудио защищены.
- Лимиты мягкие: активные/недавние файлы и офлайн-загрузки могут превышать бюджет. База метаданных, обложки, модели и оригиналы импортированных файлов в эти бюджеты не входят.
- Тесты и временные файлы упаковщика используют `tools/.cache/tmp` на диске проекта, а не системный TEMP.

Повторный замер выявил продолжающийся рост старой 0.3.1: **9 349 397 685 B** в `data/cache`, ещё **752 005 285 B** в `data/remote`. Поэтому установленное приложение обновлено до **0.3.2** и перезапущено. Установщик завершился с кодом 0; в журнале новый backend готов в 15:51:32 UTC. До обновления сделана согласованная SQLite backup на E. После обновления 238 исходных ID треков сохранены, quick_check — ok. Профиль остаётся на C, но теперь работает код с квотами.

## Ответ: трек скачивается или кэшируется?

Для сетевых источников воспроизведение сохраняет аудио в локальный кэш. Оно может быть вытеснено по LRU; повторный запуск тогда потребует сети. Кнопка скачивания закрепляет файл для офлайна: очистка обычного кэша его не удаляет. Наличие карточки в медиатеке или лайка само по себе не означает офлайн-загрузку. Оригиналы вручную импортированных локальных файлов отдельно от временного кэша.

Исходный аудит: `tools/.cache/disk-c-audit.json`; проверенные локальные скрипты переноса — в той же папке. Размер кэша установленной старой версии нельзя считать доказательством работы новых квот.
