# Яндекс Музыка → AutoMix

Реализовано и проверено 19 октября 2026 года. Это экспериментальный неофициальный адаптер, не партнёрская интеграция Яндекса. Он использует авторизованный legacy MP3-поток; зашифрованный `/get-file-info` не реализован. Доступность зависит от аккаунта, записи и изменений сервиса.

## Использование

1. Откройте `http://localhost:4730/#/sources`, карточку «Яндекс Музыка».
2. Подключите свой OAuth-токен. Поле также понимает ссылку после авторизации с `access_token`. Информация о неофициальной авторизации — в [документации библиотеки MarshalX](https://github.com/MarshalX/yandex-music-api). Токен вводится в приложении, не в чате; сохраняется в локальной БД и передаётся только API Яндекса.
3. Нажмите «Мои любимые треки» или введите название, исполнителя, ID либо ссылку на отдельный трек.
4. Кнопка «+» получает полный доступный MP3, проверяет декодируемость и длительность, добавляет запись в медиатеку и запускает фоновый анализ/подготовку вокала. До окончания загрузки повторное добавление заблокировано. После добавления доступна кнопка прослушивания; несколько подготовленных результатов можно слушать одной очередью.
5. «Волна Яндекса» получает рекомендации и подготавливает ближайшую пару. В одной партии — до двух готовых песен и максимум три попытки новых загрузок. Поддерживаются уже имеющиеся записи; Live/Remix и заметно отличающиеся длительности не подменяются оригиналом по одному названию.

Для вокальных партий используется существующий локальный `STEMS_PYTHON`. При отсутствии Python обычное воспроизведение/анализ работают, а готовые партии в кэше доступны. При ещё неготовой партии применяется обычная стратегия AutoMix; подготовка не блокирует воспроизведение всей библиотеки.

## Как устроено

`каталог/лайки → метаданные API → download-info → полный MP3 → проверка → SHA-256 → медиатека → MIR + локальные stems → PCM/AudioWorklet`.

- Браузер присылает только выбранный ID: название, длительность и адрес аудио проверяются заново на сервере.
- Предпочитается самый высокий доступный битрейт полного MP3. Превью, отсутствие явного `preview=false`, `encraw` и другие неподдерживаемые варианты отклоняются. В этой проверке сервис предоставил 192 kbps; 320 kbps или lossless для каждого трека не обещаются.
- Поддержаны числовые ID с album ID и UUID пользовательских загрузок. XML допускает шестнадцатеричную метку времени сервиса.
- Аудио сначала пишется во временный файл. После проверки сохраняется как `data-dev/remote/yandex/<SHA-256>.mp3`. Временные/подписанные URL не сохраняются как идентификаторы песни.
- В медиатеку запись попадает после успешной загрузки и проверки; отказы не оставляют неиграющую запись. Дубликаты/одновременные добавления одного ID объединяются. Обложки, когда доступны, также сохраняются локально.
- PCM, анализ и партии привязаны к проверенному хешу конкретного файла. Если скачанный заново файл изменился, он не подставляется под старые точки сведения. Явный конфликт хеша источника и трека отклоняется.
- OAuth-заголовок не отправляется на XML/CDN. Адреса и каждый redirect проверяются, тело загрузки ограничено 128 MiB. Разрешение localhost действует только для того же origin явно заданного локального тестового API.
- Поиск защищён от запоздалых результатов предыдущего запроса. Список ограничен прокручиваемой областью. Контроллер обновляет медиатеку перед запуском вновь подготовленной волны и отбрасывает её устаревший ответ при смене пользовательской очереди.

## Реальная проверка

После подключения аккаунта успешно получены 60 элементов его лайков, включая пользовательскую запись с UUID. Импортирован **STORM II — Gener8ion, Yung Lean**, provider=`yandex`:

- длительность файла **173.426917 с** при каталожной 173.380 с;
- MP3, **44 100 Hz**, около **192 kbps**;
- анализ завершён: **137.01 BPM**;
- исходный PCM 48 kHz: запросы в начале и на 100-й секунде вернули по **131072 байта** для 32768 stereo s16 frames; декодирование complete=1;
- вокальная партия HDEMUCS_HIGH_MUSDB_PLUS доступна по проверенному content hash (кэш переиспользуется при совпадении аудио);
- план локальный **FATHER → Яндекс STORM II** выбрал `tempo_bridge`: 117.99 / 137.01 BPM → общий **127.145 BPM**, **9.509 с**, B entry **4.897 с**, обе отдельные вокальные огибающие присутствуют, pending=[] (analyzer8/planner16).

Это проверка получения реального полного аудио, анализа, seek и планирования. Она не является оценкой музыкальности на слух или подтверждением доступа ко всему каталогу.

На отдельном локальном источнике с синтетической музыкой браузер выполнил подключение, получение лайков, добавление двух файлов и переход AudioWorklet (`forced=false`, `late=false`); console warn/error пусто. Тестовая БД и токен изолированы от основной медиатеки.

Автотесты адаптера: `npx vitest run apps/server/test/yandex-audio.test.ts` — **36/36**. Есть полная загрузка/seek/реальный MIR worker, preview/неподдерживаемые форматы, повреждённый транспорт, неверная длина, редиректы, OAuth, UUID/hex XML, канонические хеши, Live-версии, дубликаты, предел подготовки волны и готовый vocal f32 API без запуска Python. Тесты используют синтетическое аудио и локальные HTTP-серверы.

Финальный полный прогон: **311/311**, 17 тестовых файлов. `npm run typecheck` и production `npm run build` завершились успешно. Реальная карточка импортированного трека в браузере: [снимок](screenshots/yandex-real-import.png), console warn/error=[]; исходная очередь при этой проверке не запускалась заново.

## Границы

Полный поток не гарантирован для каждого аккаунта или трека; ошибка отдельной песни не даёт оснований обходить ограничения доступа. Наличие подписки и технического PCM не является отдельной лицензией на публикацию миксов или использование каталога в распространяемом приложении. Условия сервиса и права на конкретное использование рассматриваются отдельно.

Spotify в этом адаптере не участвует. Исследование его официальных партнёрских DJ-интеграций и неофициальных клиентов: [streaming-sources-followup.md](streaming-sources-followup.md).
