# Качество звука движка (DSP)

Проход 20.10.2026. Затронуты только `packages/core/src/dsp/*` и `packages/core/src/engine/*`; планировщик не менялся. Каждое изменение закреплено тестом, который падает на прежнем коде.

## Растяжение (WSOLA)

**Проблема.** Допуск поиска ±6 мс меньше полупериода баса: у 50 Гц период 20 мс. Часто в окне поиска не было кандидата в фазе, и растянутый бас «бился». Прошлое сравнение (`dj-automix.md`) не содержало низкого баса, поэтому этого не заметило.

**Решение.**
- Допуск ±12 мс: совпадающий цикл находится для баса от ~42 Гц.
- Предпочитается прежний диапазон ±6 мс, если широкий совпадает лучше не более чем на 1 % (меньше дрейф долей). Больший запас уже возвращал скачки фазы баса.
- Грубый поиск идёт по копиям, прорежённым 4:1 (усреднение по 4 отсчёта, ~11 кГц). Затем уточнение на полной частоте ±4 отсчёта. Поэтому вдвое больший диапазон стоит меньше прежнего поиска.

**Измерения** (синтетика, 44,1 кГц, растяжение 3–8 %; остаток после МНК-подгонки известных частот, блоки 80 мс):

| | было | стало |
| --- | ---: | ---: |
| Бас 49 + 98 Гц, SNR | 6–12 дБ | 33 дБ (как без растяжения) |
| Аккорд (12 гармоник), SNR | 9–13 дБ | 23–24 дБ |
| Ударные, SNR после выравнивания | 7–34 дБ | 27–60 дБ |
| Ошибка атак, среднее / макс. | 4,4–6,2 / 7,4–9,8 мс | 2,0–5,1 / 3,7–8,9 мс |

Тест: `keeps a 49 Hz bass line phase-coherent` (`dsp.test.ts`), прежний код даёт 11,4 / 6,8 / 8,1 дБ при пороге 25 дБ. Тест выравнивания долей в beatmatch (`engine.test.ts`) проходит без изменения порогов.

Фазовый вокодер или гибрид гармоник/ударных не делались: растяжение ограничено 8 %, а после исправления баса WSOLA на тональном материале упирается в предел метрики.

## Призрак голоса в аккомпанементе

Аккомпанемент получается как `оригинал − партия`. На всех 44 треках медиатеки он остаётся коррелирован с голосом: α = ⟨O,V⟩/⟨V,V⟩ = 1,04–1,2 в полосе 150–2500 Гц и до 2 выше 2,5 кГц. Ни в одном 8-секундном сегменте α не меньше 1,0. Значит, Demucs недооценивает голос (мягкая маска, реверберация и дубли попадают в «остальное»), и в аккомпанементе слышен его след.

Микшер теперь сам подбирает масштаб вычитаемой партии:
- по загруженным чанкам той области, где маска будет закрывать голос;
- только блоки по 2048 кадров, где партия не тише −10 дБ от микса;
- один блок на деку за вызов `process` (~16× быстрее реального времени, несколько микросекунд на квант);
- масштаб = 1 + 0,6 (α − 1), не больше 1,15; фиксируется на всё сведение (`VocalPcmSource.scale`). Меньше 0,5 с голоса — масштаб 1.

Проверка вне выборки (α оценивается на 24 с, качество — на всех сегментах трека; 44 трека): голосовой след в аккомпанементе −21,6 → −28,7 дБ (150–2500 Гц), −16,1 → −19,4 дБ (2,5–16 кГц). Хуже не стало ни у одного трека. Усадку 0,6 и потолок 1,15 выбрали потому, что 0,7 / 1,25 ухудшали один трек на 3,9 дБ.

Тесты (`vocal-handoff.test.ts`): партия с 80 % голоса оставляла ровно 0,200 голоса, теперь меньше 0,1; точная партия не пересубтрагируется (меньше 0,01).

Это не устраняет артефакты разделения. Утечки инструментов в партию голоса и ошибки на отдельных словах остаются.

## Щелчки и автоматизация

- Во всех 1892 планах нет ступенек автоматизации (короче 5 мс): самые быстрые — 80 мс у маски голоса и 55 мс у посыла вокального эха.
- Если деку убрали посреди сведения (`unload`/замена), оставшаяся раньше скачком возвращала громкость и EQ к единице. Теперь они плавно идут к единице за 0,3 с. Тест `the surviving deck glides back to unity`: скачок 60 Гц 0,115 → < 0,02.

## True peak в анализе громкости

`LoudnessMeter` использует нормированное ядро 4× лимитера и проверяет точки между отсчётами, а не только по новому отсчёту. Синус fs/4 с отсчётами мимо гребней: было −0,68 дБ (−0,37 дБ в тесте), стало ±0,05 дБ. Версия анализатора не повышалась: ограничение по true peak в `normalizationGain` при цели −16 LUFS не срабатывает ни у одного из 44 треков, планы не меняются.

## Что измерено и оставлено

- **Ресемплинг ffmpeg 44,1 → 48 кГц.** swr по умолчанию и soxr одинаковы ниже 20 кГц: шум −93,9 против −94,8 дБ (предел окна). swr оставляет только ультразвуковые зеркала (−39,5 дБ). Смена потребовала бы синхронно менять ресемплинг партий (`stems.ts`), иначе вычитание разойдётся.
- **Кроссовер LR4.** Полосы синфазны: при любых усилениях АЧХ лежит между усилениями полос, провалов нет.
- **Нормализация громкости.** Цель минус интегральная громкость, при этом лимитеру остаётся не больше 3 дБ пиков. Это планировщик, не менялось.

## True-peak лимитер

Сетка 4× сама по себе пропускает гребень синуса около 0,4 fs: он лежит до 0,45 дБ выше любой точки сетки. Независимый измеритель 16× показывал на выходе −0,56 dBTP при потолке −1 dBTP. Теперь:
- полнополосное ядро: 24 точки на ветвь вместо 12, Kaiser β=6. Ядро на 0,95 полосы на ярких мастерах читало до 0,011 дБ ниже независимого измерителя аудита. Задержка +6 кадров (0,14 мс);
- вершина параболы через соседние точки сетки, если точка — экстремум;
- запас детектора 0,05 дБ на остаточную ошибку интерполяции.

Результат на синусах 0,1–0,47 fs (16× измеритель): выход от −1,06 до −1,02 dBTP. Тест `holds the ceiling for a hot sine` (`dsp.test.ts`): старый код −0,56 dBTP при допуске −0,98. Эталон хронологии лимитера в `realtime-dsp.test.ts` повторяет новое обнаружение, допуск 1e-6 тот же.

## CPU AudioWorklet

Худший случай: обе деки растягиваются на 6 %, маски голоса на обеих, вокальное эхо, EQ; кванты по 128 кадров; Node 22. Замер чередовал «до» и «после» дважды, параллельно шёл аудит. Ниже медиана мс на секунду звука и p99.9 времени кванта:

| | 44,1 кГц | 48 кГц |
| --- | ---: | ---: |
| До | 50–51 мс, 1,29–1,42 мс | 57–58 мс, 1,54–1,56 мс |
| После | 47–48 мс, 1,16–1,29 мс | 51–53 мс, 1,30–1,44 мс |
| Бюджет кванта | 2,90 мс | 2,67 мс |

Более быстрый поиск WSOLA с запасом покрывает вдвое длинное ядро лимитера и подбор масштаба партии. Это около 5 % одного ядра; на ноутбуке вдвое медленнее остаётся больше чем 5× запаса.

## Аудит медиатеки

`npx tsx tools/audit-library.ts --render --voice-tail --audio --pairs 64 --tag dsp-quality3` против снимка ядра со старым DSP (`dsp-before`): те же 64 плана `am-planner-v2-5`, все идентичны.

| | эталон v2-3 | до | после |
| --- | ---: | ---: | ---: |
| Завершено / ошибки / недогрузки | 64 / 0 / 0 | 64 / 0 / 0 | 64 / 0 / 0 |
| Макс. true peak (независимый 4× измеритель) | −1,000 | −1,000 | −1,051 dBTP |
| Макс. работа лимитера | 0,80 | 0,79 | 0,91 дБ |
| Средний / худший провал | −2,48 / −7,93 | −1,90 / −7,12 | −1,89 / −7,12 LU |
| Хвост старого голоса, макс. RMS | −56,2 | −56,2 | −56,2 дБ |

Эталон v2-3 сделан на старом планировщике, поэтому провалы с ним напрямую не сравниваются. Лимитер стал работать сильнее на двух парах из 64. Для пары «Бассок → Валентина» (beatmatch) проверено, что дело не в растяжении: WSOLA не поднимает пики выше исходника (0,00 дБ сверх исходника и у старого, и у нового). Другое положение кадров даёт другую сумму после фазовых сдвигов кроссовера на мастере с пиками +0,5 dBFS.

Приватные примеры для прослушивания (только `data-dev/reports`): `previews/dsp-quality3/*.mp3`. Для A/B самых сильных растяжений есть `previews/dsp-before-ab1/` (До замка → Беспечный рыцарь тьмы, 9,6 %) и `previews/dsp-before-ab2/` (утекай → andy warhol, 8,8 %) — это те же планы со старым DSP.
