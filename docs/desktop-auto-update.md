# Обновления MORA через GitHub Releases

Текущая Windows-сборка использует Tauri и NSIS. Адаптер `apps/desktop-tauri/app-updater.mjs` читает прежний GitHub-канал `Rizen1322/MORA`, проверяет размер и SHA-512 установщика и передаёт его нативной оболочке. `electron-builder` используется только для создания совместимого NSIS-установщика; Electron в текущем приложении нет. Renderer не передаёт адреса обновлений, команды или пути к установщику. Исторические версии Electron, начиная с 0.3.14, использовали `electron-updater` с тем же каналом.

## Поведение

- Проверка запускается через 15 секунд после старта, затем раз в 6 часов. В настройках есть ручная проверка.
- Автоматическая проверка не скачивает установщик. Пользователь видит доступную версию и размер, затем нажимает «Скачать обновление».
- Во время загрузки музыка продолжает играть. Доступны прогресс и отмена.
- Загрузка записывается потоком во временный файл и проверяется по размеру и SHA-512 из `latest.yml`. Только проверенный файл становится доступен для установки; ошибка или отмена удаляет временную копию.
- Готовое обновление устанавливается только по кнопке и после нативного подтверждения. По умолчанию в диалоге выбран ответ «Позже».
- Обычный выход, закрытие в трей или наличие скачанного установщика сами по себе установку не запускают.
- Переустановка запускается тихо, после подтверждения; MORA перезапускается после завершения. Нативная оболочка сохраняет состояние воспроизведения и останавливает backend перед запуском установщика. При отказе запуска установщика backend и воспроизведение восстанавливаются.
- Установка запрещена во время переноса медиатеки. NSIS сохраняет профиль, `appId` и `deleteAppDataOnUninstall=false` не менялись.
- Предварительные версии и откат на меньшую версию отключены. Проверка и установка недоступны в режиме разработки.
- При сетевой ошибке, отмене или повреждённом файле текущая версия остаётся рабочей. Это не обещание автоматического восстановления после любого сбоя ОС во время установки.

Обновление yt-dlp в настройках остаётся отдельной функцией.

## Первый переход

**0.3.13 нужно обновить вручную до последней версии**: в старой программе нет кода автообновления. После этого следующие версии можно получать из приложения. Одной публикации `latest.yml` недостаточно, чтобы добавить функцию в уже установленную 0.3.13.

## Публикация

1. Увеличить версию в `apps/desktop-tauri/src-tauri/tauri.conf.json`, `apps/desktop-tauri/src-tauri/Cargo.toml` и записи приложения в `Cargo.lock`.
2. Прогнать тесты и typecheck, собрать общие ресурсы, Tauri и unified installer по [инструкции](../apps/desktop-tauri/README.md). Не использовать корневой `desktop:package`: он собирает старую Electron-оболочку.
3. Проверить `apps/desktop-tauri/dist-unified/latest.yml`: его версия, имя, размер и SHA-512 должны соответствовать готовому `MORA-Setup-<версия>.exe` из той же папки. Канал адаптера должен оставаться `https://github.com/Rizen1322/MORA/releases/latest/download/`.
4. Создать тег и **черновик** GitHub Release. Загрузить `MORA-Setup-<версия>.exe`, его `.blockmap`, `latest.yml` и контрольную сумму `.sha256`.
5. Проверить загрузку всех файлов и только затем опубликовать обычный release как latest. Не включать предварительную версию в стабильный канал и не заменять файлы уже опубликованной версии.

Пример для версии 0.4.15 после создания соответствующего тега (для следующего выпуска заменить версию во всех именах). `.sha256` нужно сформировать отдельно из готового EXE:

```powershell
gh release create v0.4.15 apps/desktop-tauri/dist-unified/MORA-Setup-0.4.15.exe apps/desktop-tauri/dist-unified/MORA-Setup-0.4.15.exe.blockmap apps/desktop-tauri/dist-unified/MORA-Setup-0.4.15.exe.sha256 apps/desktop-tauri/dist-unified/latest.yml --verify-tag --draft --title 'MORA 0.4.15' --notes-file release-notes.md
gh release edit v0.4.15 --draft=false --latest
```

Команды запускаются в клоне `Rizen1322/MORA`. Упаковщик использует `--publish never`: обычная локальная сборка сама ничего не публикует. Нельзя публиковать метаданные раньше бинарных файлов.

## Доверие и ограничения

Сейчас установщик не подписан сертификатом Windows. Проверка целостности SHA-512 и HTTPS не заменяет подпись издателя: доверие распространяется на GitHub-репозиторий и его release-метаданные. В адаптере Tauri нет проверки подписи издателя. При добавлении сертификата нужно проверять ожидаемого издателя до запуска установщика и отдельно проверить переход с неподписанных версий.

Тесты текущего адаптера покрывают потоковую запись, отмену, ошибки сети и диска, размер, SHA-512 и повторную загрузку. Тест оболочки проверяет восстановление после отказа запуска установщика. Тесты общего `AppUpdates` покрывают состояния, повторные команды и расписание. Исторические интеграционные тесты `NsisUpdater` относятся к прежней Electron-оболочке. Синтетические тестовые установщики не исполняются.

Полная замена установленного приложения требует отдельной проверки Windows-установки; модульные тесты её не доказывают. Подписанная сборка, восстановление после отключения питания и антивирусные блокировки требуют собственного испытания.
