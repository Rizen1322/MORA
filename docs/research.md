# Исследование: источники музыки и движки AutoMix

Актуальное дополнение: [Яндекс / Spotify и альтернативные клиенты](streaming-sources-followup.md). Важные уточнения к первоначальному обзору ниже: Spotify имеет официальные партнёрские DJ-интеграции; librespot технически предоставляет декодированные samples; независимые клиенты Яндекса умеют получать аудио. Ограничения публичных API и разрешение обработки нужно отличать от технического доступа. Первоначальная таблица описывает реализованные адаптеры этого приложения, а не все возможности сторонних клиентов.

Дополнение от 19.10.2026: [Apple AutoMix: подтверждённые технологии, ограничения и собственная реализация](apple-automix.md). Закрытые алгоритмы Apple не выдаются за известные; входы внутри песни и правила переходов реализованы самостоятельно.

Дата проверки: 19.10.2026. Исследование ограничено по времени: цель была выбрать архитектуру, а не написать обзор рынка.

Обозначения способа проверки:

- **[док]** проверено по официальной документации или условиям использования;
- **[код]** проверено чтением исходного кода (клон репозитория или `gh api`);
- **[запуск]** проверено реальным запросом или запуском с этой машины;
- **[не проверено]** вывод сделан по косвенным данным, явно помечен.

Для каждого источника разделены четыре разные возможности: **метаданные**, **управление официальным плеером**, **доступ к аудиопотоку** и **разрешение на обработку** (анализ, time stretching, наложение треков). Наличие stream URL не означает разрешения на AutoMix.

## Яндекс Музыка

Ссылки: https://github.com/MarshalX/yandex-music-api, https://ym.marshal.dev/

- **Официальность.** Публичного официального API нет. Библиотека MarshalX неофициальная, LGPL-3.0, активно поддерживается (последний push 10.10.2026, ~1.3k звёзд) **[код]**.
- **Авторизация.** Заголовок `Authorization: OAuth <token>` и заголовок клиента `X-Yandex-Music-Client: YandexMusicAndroid/...` (`utils/request_base.py`) **[код]**. Получение токена в библиотеке идёт через device-авторизацию с идентификаторами официального приложения. Мы этого не повторяем: пользователь сам вставляет свой токен, приложение не встраивает чужие client ID/secret.
- **Радио («Моя волна»).** Актуальный способ: сессии `POST /rotor/session/new` с сидами (`user:onyourwave`, `genre:rock`, `track:<id>`), `POST /rotor/session/{id}/tracks` для следующей партии и `POST /rotor/session/{id}/feedback` с событиями `radioStarted`, `trackStarted`, `trackFinished`, `skip` (`_client/rotor_sessions.py`) **[код]**. Есть также `rotor/wave/last` и настройки волны (`_client/wave.py`).
- **Каталог, поиск, лайки, плейлисты.** Есть методы поиска, `users/{uid}/likes/tracks`, плейлисты пользователя **[код]**.
- **Доступ к аудио.** `GET /get-file-info` требует подпись `sign`, вычисляемую ключом `DESKTOP_SIGN_KEY` из клиента Яндекса (`utils/sign_request.py`), а старый путь `download-info` строит ссылку через захардкоженную соль `SIGN_SALT` (`download_info.py`). Транспорт `encraw` отдаёт зашифрованный файл, который библиотека расшифровывает **[код]**. Это извлечённые секреты чужого приложения и обход защиты контента. **Не используем.**
- **Условия.** Пользовательское соглашение Яндекс Музыки не даёт разрешения на сторонние клиенты и обработку потока **[не проверено юристом]**.
- **Вывод.** Адаптер Яндекса в приложении экспериментальный и отключён по умолчанию. С токеном пользователя он может прочитать «Мою волну» Яндекса и лайки как **источник рекомендаций**, а воспроизводит только те треки, которые нашлись в ваших собственных файлах (сопоставление по исполнителю и названию). Обратная связь в rotor отправляется только для реально прослушанных совпадений. Без токена проверить работу с реальным аккаунтом не удалось; адаптер проверен на mock-сервере.
- **Мобильная перспектива.** Неофициальный API может сломаться в любой момент; строить на нём продукт нельзя.

## SoundCloud

Ссылки: https://developers.soundcloud.com/docs/api/guide, https://developers.soundcloud.com/docs/api/terms-of-use, https://developers.soundcloud.com/docs/api/rate-limits, https://github.com/soundcloud/api

- **Регистрация и OAuth.** Каждый запрос требует зарегистрированного приложения; OAuth 2.1: Authorization Code + PKCE для действий от имени пользователя и Client Credentials для публичных ресурсов. Токен живёт около часа, refresh token одноразовый **[док]**. Открыта ли регистрация для всех, документация явно не говорит (рекомендуемый путь через Artist Pro CLI) **[док]**.
- **Потоки.** Поле `access`: `playable`, `preview`, `blocked`. Воспроизведение через транскодированные потоки (AAC); у `blocked` нет `stream_url` **[док]**.
- **Лимиты.** 15 000 запросов к `/tracks/:id/stream` за 24 часа на `client_id`; токены Client Credentials: 50 за 12 часов на приложение, 30 в час на IP **[док]**.
- **Условия, ключевое.** Запрещено изменять контент («adaptation, editing, excerpting, or creating derivative works») без явного согласия загрузившего; запрещено создавать сервис, который агрегирует контент разных пользователей в on-demand сервис, смешивает воспроизведение с контентом других сервисов, а также веб-радио; кэш только на сессию, без офлайна; запрещено подавать контент на вход AI-технологиям, включая разделение на stems **[док]**.
- **Вывод.** Даже при наличии ключей AutoMix (time stretching, наложение, смешивание с локальными файлами) противоречит условиям. В приложении SoundCloud показан как «недоступен для AutoMix», без фиктивного подключения.

## Spotify

Ссылка: https://developer.spotify.com/policy

- **Условия.** III.7: «Do not permit any device or system to segue, mix, re-mix, or overlap any Spotify Content with any other audio content»; III.5: нельзя интегрировать с потоками других сервисов; III.13: нельзя анализировать Spotify Content; III.14: нельзя обучать модели **[док]**.
- **Вывод.** Web Playback SDK не даёт PCM и не может быть источником для DJ-движка. Spotify не подключается; карточка источника объясняет причину.

## Audius

Ссылки: https://docs.audius.co/api/, https://docs.audius.co/developers/introduction/overview

- **Документация.** REST API даёт «read-only access» к поиску, стримингу треков, пользователям и плейлистам **[док]**. Страница справочника при загрузке не содержит текста эндпоинтов (рендерится скриптом), поэтому детали взяты из README SDK: ключ API можно использовать на клиенте, bearer token только на backend **[док, README SDK]**.
- **Запуск.** `GET https://api.audius.co/v1/tracks/trending` с этой машины возвращает HTTP 403 Cloudflare, с `app_name` и без; страница условий API тоже 403 **[запуск]**.
- **Вывод.** Адаптер реализован (поиск, тренды, поток, опциональный `AUDIUS_API_KEY`), состояние определяется реальным запросом при открытии страницы источников. Анализ и смешивание для Audius выключены, пока условия использования не проверены вручную; без этого доступно только воспроизведение без наложения.

## Jamendo

Ссылки: https://developer.jamendo.com/v3.0/docs, https://devportal.jamendo.com/api_terms_of_use

- **Авторизация.** Нужен `client_id` из личного кабинета разработчика; OAuth2 для пользовательских действий **[док]**.
- **Контент.** Музыка под лицензиями Creative Commons; использовать нужно «in conformity ... [with] the license under which» трек опубликован **[док]**.
- **Условия.** Бесплатно только для некоммерческого использования; приложение не должно быть «specifically designed to cache the content nor offering an offline access»; кэш только «reasonably necessary»; нужна атрибуция автора и прямая ссылка на страницу трека; учётные данные «strictly personal» **[док]**. Числовые лимиты не указаны.
- **Вывод.** Адаптер реализован: поиск и воспроизведение через наш движок с AutoMix для персонального некоммерческого прослушивания, кэш PCM только на время сессии, ссылка на страницу трека и автора показывается. `client_id` хранится на локальном backend и не попадает во frontend bundle. Без ключа статус «требуется client_id».

## Navidrome / Subsonic

Ссылка: https://www.navidrome.org/docs/developers/subsonic-api/

- **Совместимость.** Subsonic API 1.16.1 с исключениями и частью расширений OpenSubsonic; `search3` поддерживает только простой поиск; есть `stream`, `download`, `getCoverArt`, `star`/`unstar`, `scrobble`, плейлисты **[док]**.
- **Авторизация.** Стандарт Subsonic: `u`, `t = md5(password + salt)`, `s = salt`, `v`, `c`, `f=json` (спецификация Subsonic) **[док Subsonic, не проверено на живом сервере]**.
- **Доступ к аудио.** `stream?format=raw` или `download` отдают исходный файл; наш backend декодирует его ffmpeg и получает PCM. Seek и предварительная буферизация выполняются по локальному кэшу PCM.
- **Права.** Это ваш собственный сервер с вашей музыкой, поэтому анализ и смешивание равны локальным файлам.
- **Вывод.** Лучший внешний источник для этого проекта и для будущего телефона (собственная медиатека, доступная по сети). Адаптер проверен против mock-сервера Subsonic в тестах; живой сервер не проверялся.

## Выбор подхода

1. **Свои файлы как основа.** Полный AutoMix только там, где у нас есть законный доступ к PCM: свои файлы и свой Subsonic-сервер; Jamendo условно, с сессионным кэшем.
2. **Собственное DSP/MIR-ядро на TypeScript без зависимостей** (`packages/core`): анализ (BPM, биты, доли, фразы, тональность, громкость BS.1770, тишина, эвристика вокального диапазона), планировщик переходов, микшер с двумя деками, WSOLA, 3-полосный кроссовер LR4, лимитер. Один код работает в AudioWorklet браузера, в Node для фонового анализа и офлайн-рендера примеров и тестов, а позже переносится в нативный движок.
3. **Локальный backend на Node** (Fastify, встроенный `node:sqlite`, системный ffmpeg): импорт, метаданные (music-metadata), декодирование и кэш PCM, фоновый анализ в worker threads с отменой, хранение планов переходов, рекомендации «Моей волны», адаптеры источников. Секреты хранятся только здесь.
4. **Frontend на React + Vite**, звук через AudioWorklet: точное планирование по счётчику сэмплов внутри аудиопотока, без setTimeout.
5. **Stems не обязательны.** Без нейросети вокал не детектируется; используется явно названная эвристика плотности вокального диапазона. Stem separation оставлена как будущий фоновый режим с кэшем.
