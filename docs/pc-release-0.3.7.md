# MORA 0.3.7: поиск, публичный каталог и радио

22 октября 2026. Выполнены пять ближайших рекомендаций сравнения Riff, дополнительно ускорен SoundCloud. Общий AudioWorklet/AutoMix сохранён, новых зависимостей и внешнего сервера обработки нет. Изменения AutoMix P1 из отдельного отчёта готовятся следующим этапом и не приписываются этому релизу.

## SoundCloud

Прямой поиск метаданных публичного веб-клиента, без subprocess на обычный запрос. Публичный идентификатор клиента извлекается из ограниченного набора официальных assets и хранится 30 минут в памяти; аккаунт, cookies и пользовательские токены не нужны. Desktop использует Chromium networking. Бюджет 4 секунды, контроль размера потока, отмена и cooldown после сбоя; при ошибке — независимый прежний `scsearch` yt-dlp в общем 15-секундном бюджете поиска.

Измеренный запрос «Yanix Верить»: bundled yt-dlp 5735 мс cold / 4398 мс повторно; прямой путь 1115 мс cold. Другие запросы после bootstrap: 185–364 мс. Это малая выборка одной сети, не p95 и не гарантия для другого компьютера. Подробности: [soundcloud-search-performance.md](soundcloud-search-performance.md).

## Пять рекомендаций Riff

1. **Настоящий резервный поиск Music:** yt-dlp получает `music.youtube.com/search?...#songs`, а не обычные YouTube-видео под подписью Music. Общий deadline включает ожидание очереди и оба пути. Реальный smoke: пять песен за 1227 мс.
2. **Общий незавершённый поиск:** одинаковые source/query используют один worker; уход одного подписчика не отменяет остальных, уход всех прекращает работу. Ошибки не кэшируются; готовые результаты остаются в ограниченном LRU.
3. **Прогрев по намерению:** 600 мс устойчивого наведения/фокуса/выбора с клавиатуры; touch hover не запускает работу. Только metadata, до одного speculative resolver, свободный слот для playback, четыре записи в памяти на 45 секунд. Подписанные URL проверяются на близкое истечение. При выборе записи yt-dlp переиспользует свой info JSON; файлы появляются только при фактической загрузке. Retry без прогрева разрешён до публикации partial audio, не перезаписывает файл, уже потребляемый PCM decoder. Медиатека не меняется от наведения. Реальный отдельный замер одного трека: download 2426 мс cold; metadata заранее 1534 мс + download после выбора 882 мс. Это перенос ожидания до клика, не исчезновение сетевой работы.
4. **Артисты и альбомы без Яндекса:** подтверждённые музыкальные ID, фото, популярные записи, релизы и список альбома. Кликабельные кредиты отдельно от кнопки play. Совместные авторы без подтверждённого ID ведут на свою локальную страницу, не на первый ID. Artist показывает первую подборку источника; UI сообщает о неполноте, пагинации пока нет. Проверено на Yanix: пять популярных записей, 20 релизов; альбом — 10 записей. Общий существующий плеер.
5. **Больше кандидатов радио:** отдельный WEB YouTube Mix дополняет Music up-next при недостаточном пуле. Когда оба пусты, опциональный Deezer metadata fallback: точный артист, до трёх записей, максимум два поиска одновременно, совпадение title/artist и длительности. Метаданные не являются аудио Deezer. Сохраняются наш taste-ranker, дизлайки, история и режим для микса; устаревший start/refill отменяется. [Подробная проверка радио](radio-candidates-0.3.7.md).

Сравнение исходников и ограничения: [riff-comparison.md](riff-comparison.md). Полный MIT LICENSE Riff добавлен в desktop THIRD_PARTY.md с зафиксированным commit. Настройки отключения TLS-проверки и webSecurity не перенесены.

## Проверка

- **718 тестов / 75 файлов**, проверка типов и production web build проходят. При параллельном сжатии установщика один длинный engine render превысил стандартные 60 секунд; полный повтор с бюджетом 120 секунд на тест прошёл за 88,89 секунды, без изменения проверяемых условий. Итоговая команда: `npm test -- --testTimeout=120000`. Checksum установщика и сохранность базы — в `release-0.3.7.json` после обновления.
- Реальный HTTP regression: завершение чтения тела POST не должно отменять прогрев; отключение клиента должно отменять. Отмена привязана к закрытию незавершённого ответа.
- В браузере проверены поиск → артист → альбом, запуск «Лёд» через существующий плеер и пауза. Скриншоты: `screenshots/desktop/public-artist-0.3.7.png`, `public-album-0.3.7.png`.
- Финальный packaged-backend smoke в Electron с чистым PATH и новым профилем: Music search 441 мс; SoundCloud 1118 мс, 13 результатов с 13 обложками; прогрев завершён за 1865 мс, медиатека не изменилась; артист/альбом открылись; после прогрева первый блок PCM за 982 мс, 65536 байт, JPEG-обложка 56107 байт. Это измерение получения PCM, не audible latency.

Прямой CDN/HLS streaming в отдельный HTML-плеер не переносился: он обошёл бы наш DSP. Текущий растущий файл и metadata reuse сохранены. Экспорт аудио с эффектами, полнотекстовая биография/пагинация и iOS — отдельные проекты, не скрытые части этого обновления. Сеть друга и субъективное качество радио не проверены.
