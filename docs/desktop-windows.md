# MORA для Windows

20 октября 2026. Первая сборка настольного приложения из текущего проекта: тот же React-интерфейс, тот же Fastify-backend, тот же AudioWorklet-микшер и DSP `packages/core`. DSP, планировщик, пороги и музыкальные алгоритмы не менялись. Приложение называется **MORA**; «AutoMix» остаётся названием режима переходов (янтарный цвет).

## Что получилось

- Установщик `apps/desktop/dist/MORA-Setup-0.1.0.exe` (NSIS, на пользователя, выбор папки) и portable-папка `apps/desktop/dist/win-unpacked` (`MORA.exe`).
- Запуск без терминала, Node, Python и системного FFmpeg: проверено на packaged-сборке с PATH из одних `C:\Windows` и `C:\Windows\System32`; backend сообщил встроенный `ffmpeg n9.0.2`, а не системный 9.0.1.
- **Сборка не подписана** сертификатом (`Get-AuthenticodeSignature` → `NotSigned`). SmartScreen покажет предупреждение при первом запуске. Для релиза нужен сертификат (переменные `CSC_LINK`/`CSC_KEY_PASSWORD` для electron-builder).

## Команды

```bash
npm install
node apps/desktop/scripts/fetch-ffmpeg.mjs        # один раз: LGPL-сборка FFmpeg, проверка SHA-256
npm run desktop:dev                                # собрать web+backend и открыть окно на исходниках
npm run desktop:package                            # установщик + win-unpacked в apps/desktop/dist
npx electron apps/desktop/scripts/make-icons.mjs   # пересобрать иконки из logo.png
```

`npm run package:dir -w @automix/desktop` собирает только папку без установщика. Скрипт `apps/desktop/scripts/build.mjs` кладёт web в `apps/desktop/build/web` (а не в `apps/web/dist`, которую может раздавать запущенный браузерный сервер), бандлит backend и analysis worker esbuild-ом, копирует Python-скрипты и FFmpeg.

## Архитектура

```
MORA.exe (main, src/main.mjs)
├─ окно BrowserWindow: sandbox, contextIsolation, без nodeIntegration
│   └─ renderer: http://127.0.0.1:<случайный порт>/  ← React + AudioWorklet (единственный транспорт)
│      preload.cjs → window.automixDesktop (фиксированные каналы с проверкой аргументов)
├─ utilityProcess «MORA Backend» (build/backend/backend.mjs)
│   └─ Fastify + node:sqlite + worker_threads анализа + ffmpeg/ffprobe/Python дочерние процессы
├─ utilityProcess «MORA Import» (src/migrate.mjs) — только во время переноса медиатеки
└─ трей, media keys/SMTC (через MediaSession), powerMonitor
```

- **Один origin.** Backend раздаёт и web-сборку, и API на `127.0.0.1:<порт 0 → случайный>`. Поэтому AudioWorklet `addModule`, range-PCM, SSE `/api/events` и обложки работают так же, как в браузере, без подстановки base URL. Это проверено на packaged-сборке: воспроизведение, переходы, перемотка, SSE-переподключение.
- **Launch token.** Main генерирует 32 случайных байта при каждом запуске и добавляет `X-Access-Token` к запросам *только* к своему origin через `session.webRequest`. Страница токен не видит; в лог он не попадает (маскируется). Backend отклоняет запросы без токена (401), с чужим `Host` (421, защита от DNS rebinding) и с чужим `Origin` (403). Слушает только 127.0.0.1.
- **CSP** для страниц приложения: `script-src 'self'`, без eval, `connect-src 'self'`, обложки — `self`/`https:`.
- **Навигация.** Любой уход со своего origin блокируется; внешние `http(s)`-ссылки открываются системным браузером по клику (`shell.openExternal`), webview запрещён, разрешения — только fullscreen и запись в буфер обмена. Меню File/Edit отключено.
- **Секреты.** Main хранит 256-битный ключ в `secret.bin`, зашифрованном `safeStorage` (DPAPI). Ключ передаётся backend-у при запуске, тот сразу удаляет его из своего окружения, чтобы ffmpeg/Python не унаследовали. Токены провайдеров (`providers.secret`) хранятся как AES-256-GCM `enc1:…`; старые открытые записи (браузерная версия, перенесённая медиатека) шифруются при первом запуске. Браузерный режим без ключа работает как раньше.
- **Один экземпляр.** `requestSingleInstanceLock`: второй запуск показывает существующее окно и завершается; второго backend и второго AudioContext нет.
- **Жизненный цикл звука.** Звук живёт в renderer. «Закрыть» при включённой настройке «Закрывать окно в трей» только скрывает окно — AudioWorklet, очередь и переходы продолжают работать. «Выйти» в меню трея завершает приложение: backend получает `shutdown`, закрывает HTTP, воркеры, ffmpeg и SQLite; через 8 с main убивает его принудительно. `backgroundThrottling` не отключался.
- **Падение backend.** Перезапуск на том же порту с паузой 1–3 с; более трёх падений за 5 минут → состояние «Медиатека недоступна» с кнопкой «Продолжить» (бесконечного respawn нет). Ошибка старта → локальная страница «MORA не запустилась» с «Повторить».
- **Данные.** Профиль и медиатека — `%LOCALAPPDATA%\MORA` (кэши на гигабайты не попадают в Roaming), медиатека — `…\MORA\data`, журнал — `…\MORA\logs\automix.log` (ротация 5 МБ). Внутри установленного приложения пользовательских файлов нет.
- **Перенос медиатеки** («Настройки → Перенести медиатеку…»): системный выбор папки → подтверждение → остановка backend → отдельный процесс копирует `library`, `remote`, `covers`, `cache/stems` в `data.importing`, снимает SQLite через `VACUUM INTO` (консистентно даже если источник открыт другим сервером), переписывает абсолютные пути managed-файлов, проверяет `integrity_check`, ставит маркер `.import-complete`. Затем текущая `data` переименовывается в `data.backup-<время>`, `data.importing` → `data`. Источник только читается. При сбое во время публикации следующий запуск доводит её по маркеру; незавершённая копия без маркера удаляется. PCM-кэш, отчёты, рендеры и модели не копируются (восстанавливаются/ставятся отдельно).
- **Окно.** Старт 1280×820 DIP, минимум 960×680 (меньше — если меньше рабочая область), положение/размер/развёрнутость сохраняются; если монитор отключён или заголовок вне экранов — окно центрируется на ближайшем (`src/bounds.mjs`, тесты `apps/desktop/test/bounds.test.ts`). Заголовок встроен в дизайн: drag-область, кнопки «назад/вперёд», поиск; системные «свернуть/развернуть/закрыть» рисует Windows (`titleBarOverlay`), поэтому работают двойной клик, Snap Layouts и Aero Snap. Alt+←/→ и боковые кнопки мыши — история приложения.
- **Система.** Media keys и панель Windows (SMTC) идут через существующий `navigator.mediaSession` контроллера; трей и сон вызывают тот же controller (`toggle/next/prev/pause`). Перед сном Windows музыка ставится на паузу и сама не возобновляется. «Папка на диске» открывает системный выбор папки.

## Лицензии

FFmpeg — LGPL-сборка BtbN (`--enable-version3`, без GPL-частей, без x264/x265), DLL динамические, `LICENSE.txt` и `SOURCE.txt` (ссылка, SHA-256) лежат в `resources/ffmpeg`. Сводка — `apps/desktop/THIRD_PARTY.md` (копируется в `resources`). Python/PyTorch/модели не распространяются.

## Не проверено и ограничения

- **Сон/пробуждение, отключение наушников, Bluetooth, смена устройства вывода** физически не проверялись. Реализована пауза перед сном (`powerMonitor.suspend`) без автоповтора; смену устройства по умолчанию отрабатывает Chromium. Реальной смены DPI на живом мониторе и переноса окна между мониторами с разным DPI не было — только эмуляция масштаба и unit-тесты размещения.
- **Интернет пропал/вернулся** для Яндекса не проверялся на живом аккаунте: проверена недоступность локальной службы; ошибки загрузки Яндекса идут прежним путём (пропуск/повтор волны).
- Импорт медиатеки через интерфейс (диалоги, остановка/перезапуск backend) не прогонялся автоматически; проверены процесс копирования и восстановление публикации.
- Подписи нет. Меню трея («Выйти», «Пауза») не нажималось автоматически: выход проверен тем же путём `app.quit` через закрытие окна при выключенном «Закрывать в трей».
- Звук не прослушивался в этой задаче; качество переходов не оценивалось — проверены только отсутствие underrun и логика транспорта.
- Расширенный анализ (разделение вокала, Whisper) в сборку не входит: готовые партии из перенесённой медиатеки используются, новые требуют Python с PyTorch (`stemsPython` в `desktop.json`, интерфейса для установки пакета пока нет).
- Thumbnail-кнопки на панели задач, автозапуск, автообновление, выбор другой папки медиатеки из интерфейса — не сделаны.
- HTTP на 127.0.0.1 оставлен для первого этапа: другие процессы того же пользователя теоретически могут подобрать порт, но без launch token API недоступен.

## Следующему разработчику

1. Тесты desktop: `npx vitest run apps/desktop/test apps/server/test/desktop-guard.test.ts`. Сценарий packaged: `node apps/desktop/scripts/smoke.mjs --profile <пустая временная папка> --tracks <папка с mp3> --out <папка отчёта>`; скриншоты: `screens.mjs`. В Git Bash добавляйте `MSYS_NO_PATHCONV=1`. Никогда не указывайте реальный профиль `%LOCALAPPDATA%\MORA`.
2. Отладка: `MORA.exe --remote-debugging-port=9333` + `AUTOMIX_DEVTOOLS=1`; журнал — `%LOCALAPPDATA%\MORA\logs\automix.log`.
3. Подпись: сертификат → `CSC_LINK`, `CSC_KEY_PASSWORD`, затем `npm run desktop:package`.
4. Ближайшее: живая проверка сна/наушников/Bluetooth на установленной сборке; пакет «Расширенный анализ» (Python embeddable + PyTorch отдельной загрузкой с прогрессом и лицензиями моделей); thumbnail-кнопки; автообновление.
