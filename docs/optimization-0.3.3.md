# MORA 0.3.3 — кэш, память и фоновая нагрузка

21 октября 2026. Изменения локальные, без внешнего вычислительного сервера. iOS отложен; текущая итерация предназначена для ПК.

## PCM: убрать дублирующую работу и гонки

Раньше `open()` переиспользовал запись только после появления процесса FFmpeg. Между асинхронным открытием источника и запуском процесса параллельный запрос мог создать вторую запись с тем же именем файла. Теперь все запросы одной записи используют общий Entry сразу после создания.

У каждого поколения подготовки своё имя `.part`. Отмена/ошибка старого поколения не удаляет новую запись из Map. Отменённый или остановленный запрос не запускает FFmpeg после позднего ответа источника; полученный поток закрывается. Просроченные запросы открытия тоже отменяются, а не только уже запущенные процессы.

Очистки PCM выполняются последовательно. Активное чтение защищает файл от LRU; ручная очистка сохраняет закреплённый текущий/следующий трек и активных читателей. Старые файлы удаляются с уступкой event loop между записями. Ожидающие читатели снимают свой таймер и callback после пробуждения. Истёкшие pins удаляются из Map. На границе атомарного переименования `.part` чтение повторяется по окончательному имени без нового декодирования.

## Сетевой кэш

Раньше размер защищённых недавних файлов исключался из суммы при проверке лимита. Например, 40 MB свежего аудио + 40 MB старого при лимите 64 MB могли оставить обе записи. Теперь свежее аудио занимает бюджет, а вытесняются доступные старые файлы. Офлайн-загрузки остаются отдельной защищённой категорией.

Пересекающиеся запросы очистки не запускают параллельный обход/удаление; более строгий запрос учитывается той же очередью. Перед очередным удалением проверяется, не закрепил ли пользователь запись для офлайна. Проверка делается по конкретному хешу, без загрузки всего списка закреплённого аудио для каждого файла. Ошибки необязательной фоновой очистки перехватываются.

## Память и анализ

- Полный анализ хранится в памяти в LRU на **64 записи**. Ограничение действует и для новых результатов worker, и при загрузке из SQLite. Ранее завершение фонового анализа обходило ограничение Map. Часто используемые записи перемещаются в конец LRU; вытесненные результаты остаются в базе и загружаются по необходимости. Это ограничение количества, не обещание фиксированного числа мегабайт на любых записях.
- Worker анализа переиспользует выровненный interleaved-буфер при декодировании, вместо нового Float32Array на каждом блоке FFmpeg. Числовая обработка звука сохранена.
- Вытеснение вокального кэша освобождает также связанные данные текста/качества в памяти.
- Подготовка `candidate` защищает PCM на 30 секунд вместо 10 минут и не получает приоритет текущей/следующей записи при выделении вокала. Более короткий pin не сокращает уже действующую защиту воспроизведения.

## Фоновое распознавание и GPU

Запуск программы больше не запускает Whisper по всем готовым вокальным партиям библиотеки. Распознавание слов запрашивается для текущей/следующей записи. Данные уже готовых текстов и таймингов сохраняются. CPU-потоки Torch в процессе распознавания ограничены 1–4, как в разделителе вокала. Фактическое время inference этим релизным тестом не измерялось.

На паузе полноэкранный фон ограничен **8 fps**, скульптура волны — **12 fps** вместо 30 и 24. Во время воспроизведения сохранены пределы 30 и 45 fps. Остановка скрытых визуализаций и Reduce Motion сохраняются. Уменьшение числа кадров — ограничение работы renderer, а не измеренное процентное снижение общего CPU/GPU.

## Практические границы

Квоты 512 MiB исходного сетевого кэша, 512 MiB PCM и 1024 MiB стемов остаются мягкими: закреплённые офлайн-файлы, активные/недавние записи могут превышать бюджет. Пользовательские явные настройки лимита сохраняются. Локальные оригиналы, SQLite и веса моделей не являются временным PCM-кэшем.

Не заявлено полное прекращение роста диска: офлайн-загрузки и добавление локальных файлов закономерно занимают место. Также ещё нет оконного дискового PCM для многочасовых записей: такой файл при воспроизведении может временно превысить бюджет. Это отдельный следующий этап вместе с явными leases текущей очереди и ограничением устаревшей фоновой подготовки.

Следующие технологии AutoMix на ПК остаются в `automix-ai-review.md`: ограниченные безопасные петли, voice/bed routing, затем локальная оценка коротких рендеров кандидатов. Эти функции не выдаются за уже готовые в релизе оптимизации.
