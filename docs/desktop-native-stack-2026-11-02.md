# Desktop native stack: проверка переноса

Рабочая ветка: `codex/desktop-native-stack`, отдельная рабочая копия `tools/.cache/desktop-0.3.25-source`. Стабильная версия 0.3.28 сохранена отдельно для сравнения. Изменения планировщика из общей папки не перезаписывались.

Оболочка кандидата — Tauri 2 и системный WebView2. Интерфейс остаётся на React. В отдельном Node-процессе сохраняются каталог, база SQLite и логика провайдеров; декодирование, сетевой транспорт и аудиодвижок работают в Rust. Это не полный отказ от JavaScript или Node.

Сеть использует постоянный reqwest/Tokio-процесс с пулом соединений. Загрузки звука идут в растущий файл без передачи всего аудио через JS. Сохранены отмена, ограничения размеров, проверка сертификатов, ограничения перенаправлений, приоритет текущего/следующего трека и прокси. yt-dlp продолжает разрешать адреса, решать проверки сайтов, обрабатывать HLS/DASH и импорт с извлечением звука.

Symphonia 0.6.1 с libopus декодирует проверенные WAV, FLAC, MP3, Ogg/Opus и WebM/Opus. Rubato выполняет ресемплинг. Исправленный MKV demuxer учитывает DiscardPadding, включая границы лейсованных Opus-пакетов. Для неподтверждённых форматов, включая AAC/MP4 с особенностями gapless, остаётся FFmpeg. Его нельзя считать удалённым из приложения.

Тесты сравнивают число сэмплов, временное выравнивание, начало выдачи PCM до окончания загрузки, сохранение кэша после переименования файла, отмену процессов и запас уровня выше 0 dBFS. Для одинаковой частоты WAV требуется побитовое совпадение. Для Opus и разных фильтров ресемплинга используются узкие измеренные допуски при неизменном числе сэмплов и точном повторном чтении кэша.

## Измерения декодирования

Windows, Ryzen 5 9600X; 120 секунд синтетического стереосигнала, три прогона. Первый PCM измерен через действующий Node-адаптер после предварительного probe. Память — пиковый working set отдельного процесса декодера, а не всей MORA.

| Формат | Первый PCM, native / FFmpeg, мс | Полное декодирование, с | Пиковая память декодера, МиБ |
| --- | ---: | ---: | ---: |
| WAV | 10.9 / 43.2 | 0.081 / 0.088 | 4.8 / 21.4 |
| FLAC | 12.4 / 27.3 | 0.096 / 0.092 | 4.8 / 22.5 |
| MP3 | 11.9 / 26.0 | 0.123 / 0.089 | 5.2 / 20.8 |
| WebM/Opus | 12.3 / 30.8 | 0.160 / 0.177 | 4.7 / 21.0 |

Время полного декодирования и первого PCM взято из прогона Node-адаптера; память — из отдельного прогона процессов с теми же файлами. Смешивать эти показатели в оценку общего ускорения нельзя. Синтетический сигнал не заменяет проверку всей музыкальной библиотеки.

Подробная методика и сырые результаты: `data-bench-results/native-stack/decoder/README.md`, `decoder-process-120s.json`, `node-adapter-120s.jsonl`. Воспроизведение: `tools/bench-decoder.ps1` и `packages/decoder-rust/tests/bench-adapter.ts`.

## Измерения сети

Методика, все прогоны и ограничения находятся в `docs/native-network-benchmark.md` и `docs/native-network-benchmark.json`. Это локальный транспортный стенд с одинаковыми бинарными данными и контрольными суммами. Он не измеряет скорость внешних сервисов или всего приложения.

В одинаковой оболочке Electron медиана CPU транспортной задачи уменьшилась с 656 до 280 мс, оценка суммы пиков working set процессов — с 297.9 до 206.3 МиБ. Пропускная способность изменялась значительно. В сравнении Node с Node+Rust транспортом пропускная способность ухудшилась: дополнительный процесс и локальный HTTP-мост имеют цену. Универсального ускорения сети результаты не подтверждают.

## Стенд приложения

`tools/bench-desktop-runtime.mjs` запускает только скрытые окна в новых временных профилях. Считает приватный working set, commit, сумму working set и CPU всего дерева процессов. Одинаковый тихий 60-секундный WAV импортируется через папку, чтобы тестовые буферы не раздували память интерфейса. Воспроизведение идёт с нулевой громкостью через настоящий нативный аудиохост.

Начало воспроизведения означает подтверждённое состояние аудиохоста; физическая задержка аудиовыхода не измеряется. CPU указан в процентах одного логического ядра для процессов, переживших интервал. Сумма working set дважды учитывает общие страницы, поэтому главным показателем RAM служит приватный working set. Кэш ОС не сбрасывается. Скрытый интерфейс не характеризует плавность видимого окна.

### Итоговые прогоны 3 ноября: версия 0.3.31-preview.1

Три последовательных прогона на вариант, свежие временные профили. Для Tauri измерены именно EXE и ресурсы, распакованные из NSIS без запуска установщика. Их SHA-256 сохранены вместе с результатами. Медианы:

| Вариант | RAM в покое, МиБ | RAM при воспроизведении, МиБ | CPU при воспроизведении, % одного ядра | Запуск интерфейса, мс | Команда → подтверждённое воспроизведение, мс |
| --- | ---: | ---: | ---: | ---: | ---: |
| Electron 0.3.28 | 189.7 | 248.4 | 2.82 | 376 | 171 |
| Electron + Rust 0.3.31 | 192.4 | 249.3 | 2.26 | 664 | 176 |
| Tauri 0.3.31, файлы установщика | 138.0 | 174.0 | 3.38 | 780 | 176 |

В этом сценарии Tauri использует примерно на 30% меньше приватной памяти. Выигрыш CPU не подтверждён: диапазоны перекрываются (Electron+Rust 1.32–3.76%, Tauri 2.36–3.94%). Замена оболочки не показала ускорения запуска. Первый запуск распакованного Tauri занял **13.99 с**, следующие — 0.78 и 0.69 с; причина первого долгого запуска не установлена. У Electron+Rust первый запуск тоже был дольше: 3.65 с, затем 0.66 и 0.36 с. Эти значения нельзя скрывать за медианой.

Во время проверки исправлена видимость WebView2: скрытие HWND не скрывало сам WebView, поэтому document.hidden оставался false и анимации продолжали работать. Теперь отдельная видимость WebView синхронизирована со скрытием, сворачиванием и восстановлением окна. После исправления document.hidden=true подтверждено проверкой; фоновые анимации останавливаются. Предварительные цифры до исправления не являются результатом финальной сборки.

Итоговые данные: `docs/desktop-native-stack-results-2026-11-03.json`; сырые прогоны — `data-bench-results/native-stack/electron-0.3.28-runtime-2026-11-03.json`, `electron-0.3.31-runtime.json`, `tauri-0.3.31-installed-payload-runtime.json`. Ошибочный предварительный замер, захвативший посторонние процессы из-за повторного использования PID, отброшен; стенд теперь проверяет время создания родителя и потомка.

## Исправления и проверка 3 ноября

Включён актуальный мягкий echo-out из 0.3.30. TypeScript/Rust совпали в 323 случаях; дополнительно прошли 117 тестов планировщика и два нативных теста хвоста/feedback. Ранее одобренные локальные примеры сохранены; частные фикстуры не добавлялись в Git.

Устранён повторный запрос плана после односекундного ожидания: первый refresh использует уже начатый расчёт. Тест до исправления воспроизводил два запроса, после — один. Односекундная готовность резервного перехода сохранена. Исправление есть и в основной папке проекта. Подробности: `docs/desktop-transition-preparation-2026-11-03.md`.

Основной прогон: 1261 успешный тест и один устаревший генерированный iOS bundle. После регенерации его набор прошёл 5/5; TypeScript всех приложений прошёл. Отдельно повторены 16 сетевых/обновляющих тестов. Нативная матрица декодирования и проверки прогрессивного PCM, headroom, отмены процессов прошли.

Скрытая оболочка продолжила воспроизведение с индекса 0 до 9 при замороженном WebView в течение 45 секунд; восстановление и перезапуск на паузе прошли на той же версии исходников. Файлы финального установщика отдельно выполнили три прогона реального нативного воспроизведения с подтверждённым продвижением позиции. Импорт проверен на согласованном SQLite-снимке, резервной копии, пересечении путей и перешифровании ключей; недоступный исходный ключ прерывает импорт до публикации данных.

## Границы проверки

Тестовый Tauri-профиль отделён от стабильного MORA. Импорт должен создавать согласованный SQLite-снимок, сохранять резервную копию и отклонять пересекающиеся пути. Ключи провайдеров защищены Windows DPAPI; недоступные ключи не перезаписываются.

Автообновление Tauri-кандидата отключено до отдельного подписанного канала. Стабильный канал Electron не заменяется. Проверки не меняют системные настройки прокси и не используют настоящие учётные данные. Корпоративная аутентификация, внешние музыкальные сервисы и физические аудиоустройства требуют дополнительной проверки в целевой среде.
