# MORA 0.3.25 — проверка настольного обновления

Сборка ведётся в отдельном checkout `tools/.cache/desktop-0.3.25-source` на основе исходников 0.3.24. В него перенесены изменения текущей задачи и новый TypeScript/Rust-планировщик, который параллельно дорабатывался в общей папке. Рабочая ветка пользователя не переключалась, текущие правки не сбрасывались.

Очередь обслуживает DesktopPlayback в основном процессе Electron; текущая запись подтверждается токенами Rust-движка. UI отправляет команды через NativeMix и получает подтверждённые состояния. Native PCM endpoint требует отдельный секрет основного процесса; он не передаётся странице или дочерним декодерам. Движок читает ограниченные блоки f32le/s16h из кэша. Смена имён progressive/final файла, отмена старта, короткие чтения, поколение воспроизведения и предыдущий трек проверяются отдельно.

Усиление текущей записи закрепляется при загрузке. Перепланирование не посылает новое усиление текущей деке; анализ следующей записи может обновить её усиление до вступления. Явное изменение целевой громкости остаётся доступным. В тесте временный уровень -6 dB не заменяется нулевым уровнем плана без анализа.

Планировщик включает новый filter handoff и drop swap. Сохранённые одобренные планы сохраняют точные ID: экспортируемый PLANNER_VERSION не меняется, для автоматического кэша используется новый маркер `transition-styles-2-filter-handoff`.

Финальный общий прогон checkout: 1184 теста в 153 файлах. TypeScript всех workspace прошёл. Дополнительно: 266 общих сравнений Rust/TS и 110 сравнений нового планировщика (в том числе одобренные планы и синтетические filter handoff/drop swap), допуск 1e-9. Личные музыкальные фикстуры не предназначены для публикации.

Постоянный вычислительный worker проверен на повторном использовании, ошибках, отмене активного и ожидающего запроса. Измерение 30 вызовов простого плана без анализа: отдельный процесс — медиана 12,6092 мс, p95=15,9196мс; постоянный worker — медиана 0,0759 мс, p95=0,2370мс. Это обмен данными и расчёт простого плана, а не обработка180 секунд аудио или задержка начала звучания.

Windows SMTC проверен через настоящий системный GlobalSystemMediaTransportControlsSessionManager: метаданные, обложка, timeline, Play/Pause/Next/Previous/seek и закрытие сессии. Медиаклавиши остаются резервом при недоступности helper. В общем Rust-прогоне прошли 14 unit-тестов и 2 integration-теста.

Подготовка плейлиста использует существующие загрузки и два задания анализа; планы рассчитываются последовательно. PCM всего плейлиста заранее не создаётся. Отмена не удаляет готовые записи и общие загрузки, начатый анализ может завершиться. Очистка временного кэша сохраняет скачанные оригиналы и используемый звук.

Обложка Яндекса запрашивается отдельно от аудио и сохраняется в библиотеку. Старые записи без cover_id получают восстановимый URL; повторные запросы объединяются. Пустая обложка альбома больше не подавляет обложку трека.

Переходы сохраняются основным процессом, включая быстрые переключения. Последний результат и ID журнала передаются интерфейсу; диагностика обновляет список самостоятельно.

Ограничения: проверка с нулевой громкостью не заменяет длительное прослушивание. При полном отказе страницы новый подбор рекомендаций «Волны» по-прежнему требует UI; уже переданная очередь продолжает играть. Установщик не подписан Authenticode.

Финальный установщик: `MORA-Setup-0.3.25.exe`, 170254468 байт, SHA-256 `bb013d3592cb0fc38c5251fe308ca59a8c55a69d981222b0c8139ac90955b7a0`. Манифест обновления, blockmap, Rust/SMTC и bundled host проверены скриптом verify-release.

Проверка именно упакованного приложения: 30 секунд frozen страницы, очередь продвинулась с индекса 1 до 3; четыре серии быстрых Next/Previous, ещё один Next после них; Pause/Resume, переключение выхода и восстановление после завершения дочернего Rust-процесса. 78 отчётов audioHealth: PCM underrun = 0, device underrun = 0, slowBlocks = 0, максимальное время блока 0.1996 мс, максимум p99 = 0.0599 мс. Нулевая громкость, синтетические WAV; это проверка непрерывности и управления, а не субъективной музыкальности.

GUI: отмена удаления из очереди, подготовка двух записей и одного перехода, управление диском, компактные меню, положение меню под кнопкой «Ещё», отсутствие кнопок .btn внутри него, плеер при 1280 и 960 px. Скриншоты и JSON лежат в `data-bench-results/desktop-0.3.25/`. Визуально проверен playlist-menu.png. Для скриншотов окно открыто; скрытый captureScreenshot после фокуса меню зависал в CDP, поэтому финальный прогон выполнен с --visible.
