# MORA iOS: перенос без обязательного сервера

Дата проверки: 21 октября 2026. Есть Mac у владельца; текущая рабочая среда агента — Windows. Способ распространения пока не выбран. Нативная сборка и проверка дизайна на iPhone ещё не выполнены.

## Принятое направление

SwiftUI для экранов, AVAudioEngine для воспроизведения и будущего DSP, файлы/база в контейнере приложения. Приложение не требует постоянно работающего ПК или оплачиваемого сервера. Интернет нужен только для источников/поиска/текстов; импортированная музыка работает локально.

Подготовлен проект `apps/ios/MORA.xcodeproj`, который открывается на Mac без Node. Это первый нативный этап с локальной коллекцией, а не готовая замена Windows-приложжения. Существующий веб-/desktop-код продолжает работать отдельно.

## Граница общего и нативного кода

| Часть | Решение | Текущий статус |
| --- | --- | --- |
| Планировщик переходов | Тот же TypeScript собирается в статический JS-бандл, JavaScriptCore выполняет его в utility-очереди | Бандл и JSON-мост готовы; эквивалентность desktop-планам проверена в ECMAScript VM |
| Аудиовывод | AVAudioEngine, нативное расписание аудиобуферов | Базовый плеер написан; сборка на Mac впереди |
| Исполнение переходов | Две деки, расписание по sample clock, EQ/gain/echo, сохранение pitch, ограничитель | Не перенесено; UI-таймеры и JavaScript не должны управлять каждым аудиосэмплом |
| Анализ | Декодирование средствами Apple, ограниченный PCM-буфер, MIR на utility executor, запись результата по хэшу/версии | Нужно реализовать и сравнить с эталонным ядром |
| Вокал | Исследование Core ML/другого нативного inference, короткие окна, кэш только ближайших пар | Модель не выбрана; полную Demucs на всех iPhone обещать нельзя |
| Коллекция | Application Support, атомарный архив; для большого каталога позднее SQLite | Первый файловый вариант написан |
| Офлайн | Импорт копирует проверенное аудио в постоянное хранилище | Написано, нужно испытание устройства |
| Сетевые загрузки | Background URLSession, сохраняемые задания, resume data, атомарный commit после проверки | Следующий этап, пока реализации нет |
| Источники | Native adapter по `MusicSource`, отдельные search/recommendations/resolve и capabilities | Контракты готовы, сетевых адаптеров нет |

Apple описывает нативный аудиограф и режимы рендеринга в [AVAudioEngine](https://developer.apple.com/documentation/avfaudio/avaudioengine). Фоновая загрузка должна восстанавливать URLSession с прежним идентификатором, а временный файл — переноситься в постоянное хранилище: [Downloading files in the background](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background).

## Интернет-источники: что действительно известно

Riff использует desktop-инструменты и сам указывает, что официальной iOS-версии нет; готового решения для телефона из него не получается: [README Riff](https://github.com/rootscripts/riff#mobile-versions).

Кандидат для отдельного исследования — [YouTubeKit](https://github.com/alexeichhorn/YouTubeKit). Он заявляет локальное извлечение на iOS и фильтрацию нативно воспроизводимых потоков. У него также есть **удалённый fallback**: в нашей архитектуре нельзя незаметно включать его и называть обработку полностью локальной. Первую проверку проводить с явным `.local`, фиксированным commit и набором реальных треков. Наличие библиотеки не доказывает актуальную работоспособность YouTube на устройстве/в регионе; зависимость пока не добавлена.

Spotify/Apple Music в импорте — прежде всего метаданные плейлистов. Доступность каталога, разрешение скачивания и возможность получать PCM — разные свойства. Не обещать получение аудиобайла Spotify по одной публичной ссылке. Яндекс остаётся отдельным необязательным адаптером; учётные данные хранятся в Keychain, не в plist/JS/URL-логах.

Для App Store/TestFlight отдельно проверить правила источников: [App Review Guidelines §5.2.3](https://developer.apple.com/app-store/review/guidelines/#intellectual-property) требуют разрешения на сохранение/конвертацию/скачивание медиа сторонних сервисов. Способ установки и техническая возможность извлечения не заменяют такое разрешение. Это влияет на набор функций релиза, не на автономность локального плеера.

## Как должен работать офлайн и радио

1. Хранить provider + recording ID отдельно от временной подписанной ссылки. URL обновляется при истечении, а идентичность трека/лайки/плейлисты сохраняются.
2. Пока играет текущий трек, готовить следующий и один запасной. Декодирование, поиск и анализ не должны блокировать realtime-аудиопоток.
3. Радио заранее держит 10–20 кандидатов, ранжирует по локальным лайкам/дизлайкам и истории. Загрузка/анализ ограничены памятью и температурой, не количеством кандидатов.
4. В авиарежиме выбирать только проверенные локальные файлы. Показывать, что подбор ограничен офлайном; не ждать сетевой таймаут перед каждым Next.
5. Отдельно хранить временный кэш и офлайн-файлы. Автоочистка никогда не удаляет закреплённую музыку. Состояния задания: очередь, загрузка, ожидание сети, пауза, проверка, готово, ошибка, отменено.
6. Проверять кодек, длительность и целостность до публикации файла. Resume после быстрого pause/cancel не создаёт две попытки одного задания; desktop-регрессия уже добавлена.
7. При переходе в фон продолжать аудио, но останавливать визуализацию и тяжёлый необязательный анализ. Не рассчитывать на непрерывную работу JS, WebView или фоновых CPU-задач.

## Дизайн телефона

Сохраняем зелёный акцент MORA и выразительную типографическую иерархию. Меняем структуру под телефон: три постоянно доступные вкладки, мини-плеер над ними, отдельная шторка трека. Основные действия доступны большим пальцем; вторичные — в контекстном меню или настройках.

В текущем нативном коде используются системные текстовые стили с Dynamic Type, светлая/тёмная палитра, VoiceOver, основные контролы от 44 pt, scroll на экране плеера. У яркой кнопки задан контрастный текст, размеры транспортных кнопок помещаются в ширину 320 pt. Это проверка кода, **не визуальная приёмка** на симуляторе.

Основание — локальный `skill/apple-design-skill-main/SKILL.md`: `designing-for-ios.md › Best practices` — ограничивать количество контролов и учитывать досягаемость; `tab-bars.md › Best practices` — «Use a tab bar to support navigation, not to provide actions»; `motion.md › Best practices` — «Make motion optional»; `playing-audio.md › Best practices` — использовать системное управление громкостью. Эти принципы применены к нативным экранам; финальную композицию нужно оценить на устройстве.

Следующий дизайн-проход: MORA App Icon, плавное раскрытие обложки в плеер с сохранением контекста, синхронные тексты, компактные настройки радио, адаптивная визуализация по реальному RMS/спектру. Для Reduce Motion — статичная форма. В фоне и при тепловом ограничении — без визуализации. Не использовать бесконечный декоративный 3D-цикл как имитацию реакции на музыку.

## Следующие этапы и критерии готовности

1. **Mac gate:** `sh apps/ios/scripts/check-macos.sh`, затем запуск на iPhone. Исправить ошибки Swift/SDK, проверить настоящий JavaScriptCore. Windows-проверка не заменяет этот шаг.
2. **Аудио gate:** импорт MP3/AAC/WAV/FLAC по фактической поддержке; pause/seek/Next, конец последнего трека, два файла разной sample rate; 30 минут с заблокированным экраном; наушники, Bluetooth, звонок и возврат. Не воспроизводить автоматически после сброса медиасервиса: [документация Apple](https://developer.apple.com/documentation/avfaudio/avaudiosession/mediaserviceswereresetnotification).
3. **AutoMix gate:** перенести DSP, рендерить эталонные пары, сравнивать PCM/пиковый уровень/времена вокальных передач. Огибающие исполнять по аудиочасам; при отсутствии анализа — честный fallback. Предварительно рассчитанный план сам по себе не означает работающего микса.
4. **Sources gate:** отдельная проверка нативного resolver без скрытого сервера, затем поиск, обновление URL, сетевые загрузки и радио. Протестировать 403/404/429, истекший URL, смену сети, отсутствие доступного кодека.
5. **UX gate:** 320/375/393/430 pt, большой Dynamic Type, VoiceOver, Reduce Motion/Transparency, светлая/тёмная тема, одна рука, длинные русские названия, обложка/текст, клавиатура поиска. Сохранить реальные скриншоты из симулятора.
6. **Release gate:** выбрать подпись/дистрибуцию, privacy/лицензии, app icon, резервную копию, миграции БД и тест на реальном устройстве. IPA до этих проверок готовой не считать.
