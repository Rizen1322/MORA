# ПК: Rust-ядро и локальный установщик 0.3.23

Перенос продолжает [первый этап DSP](desktop-rust-audio-2026-10-30.md). Electron/React остаются оболочкой; на Rust работают анализ BPM/тональности/структуры/громкости, автоматический планировщик, компиляция ручных сценариев, офлайн-микшер и измерение финалистов, исполнение переходов и вывод WASAPI. Декодирование выполняет нативный FFmpeg. Медиатека, сеть, кэш, учёт оценок и окончательная политика выбора измеренного финалиста остаются в сервере.

**Вокал на ПК не вырезается.** Играют оригинальные записи. Сервис разделения отключён; старые метаданные разделения не передаются планировщику, для desktop изменён ключ кэша, сохранённые вокальные маски не исполняются. Общие функции совместимости проверены отдельно, но в продукте не включены. iOS/Swift этим переносом не изменялись.

Последняя проверка серверного пути включает переход 64 секунды на 96 кГц и входной JSON больше старого лимита 128 МиБ. Лимиты запроса и результата остаются ограниченными — 256 МиБ. Проверены отмена уже работающего анализа, повторное использование worker и отсутствие оставшихся нативных процессов.

Исправления независимых проверок агентами: гонка двух запусков движка, готовность после fatal, упаковка старого бинарника при CARGO_TARGET_DIR, недостаточный размер запроса для длинного 96-кГц рендера. Для исправлений добавлены воспроизводимые проверки. Финальная независимая перепроверка подтвердила все четыре исправления и повторно прошла 14 побитовых рендеров и 13 проверок измерений; новых существенных ошибок не найдено.

Общий прогон ПК/core/server/web: **1071 тест в 134 файлах**, плюс **10 Rust-тестов**. Typecheck core/server/web/desktop прошёл.

## Производительность и ограничения

Измерения DSP относятся к release-сборке, 128 кадрам и прогретому V8. Они исключают запуск процесса, JSON/base64, FFmpeg, запись файлов и оболочку. Отдельные end-to-end времена анализа и CLI-планировщика включают другую работу и не сравниваются с ними как одна метрика.

Свежий DSP-прогон: 36 сценариев на 44,1/48 кГц, каждый трижды — **108 прогонов**, максимальное отклонение PCM **0**. Ryzen 5 9600X, Node 26.13.0, Rust 1.99.1, Windows x64. Ниже медианы трёх прогонов на 48 кГц:

| Сценарий | Ускорение DSP | TS p99, мс | Rust p99, мс |
| --- | ---: | ---: | ---: |
| Воспроизведение | 1,93× | 0,0211 | 0,0122 |
| EQ/reverb/mono/balance | 1,43× | 0,0251 | 0,0185 |
| Переход с темпом | 1,86× | 0,2334 | 0,1265 |
| Loop/roll | 1,91× | 0,0289 | 0,0154 |
| Tape-stop | 1,87× | 0,0327 | 0,0259 |
| Скорость/тон независимо | 1,08× | 0,1372 | 0,1107 |

CLI-планировщик **не ускорился**: на 170 случаях медиана вызова с запуском процесса и JSON составляла 34,03 мс против 5,44 мс у TS внутри процесса; на 36 реальных случаях — 30,08 против 2,70 мс. Тяжёлая подготовка выполняется вне серверного event loop. Ускорение приложения целиком не заявляется.

Короткая проверка настоящего Electron/WASAPI использует отдельный профиль и нулевую громкость: Play/Pause/Next, смена устройства с сохранением прежнего выхода при отказе, принудительное завершение нативного дочернего процесса и восстановление по Play. Это не замена длительному воспроизведению и прослушиванию музыки.

Проверка **упакованного** 0.3.23 прошла: 0 PCM underruns, 0 WASAPI underruns, 0 медленных блоков; максимальный интервальный p99 DSP — 0,0426 мс. Рабочий набор нативного процесса в этой короткой проверке — 20 865 024 байта, private memory — 11 952 128 байт; это не память всего приложения. Исходный release-бинарник, build/audio и ресурс установщика имеют одинаковый SHA-256.

## Локальный установщик

- `apps/desktop/dist/MORA-Setup-0.3.23.exe` — 169 925 947 байт (около 162 МиБ).
- SHA-256: `ed7d781817f8f1cbfef01146e93a2821b99d38b0c0ee9b0b775eb4801dd74351`.
- Рядом сохранены `.blockmap`, `.sha256` и локальный `latest.yml`.
- `verify-release.mjs` проверил версию в app.asar, updater, размеры, SHA-512, нативный бинарник и лицензии. Цифровой подписи Authenticode нет.
- Команда упаковки использовала `--publish never`. Установленное пользовательское приложение не обновлялось.

Установщик предназначен для локальной проверки. Публикация, git push, GitHub Release и установка поверх пользовательского приложения не выполняются. Сборка использует текущую рабочую копию с сохранением ранее существовавших изменений; git-коммит не объявляется полным снимком её исходников.
