# Перенос аудиотракта ПК на Rust — 30 октября 2026

Исторический отчёт первого этапа. Продолжение: [Rust-анализ, планировщик и установщик ПК](desktop-rust-core-2026-10-31.md).

На Rust перенесено **исполнение stemless-аудиотракта** Windows: две деки, WSOLA, автоматизация темпа и переходов по счётчику сэмплов, LR4, фильтр, loop/roll, tape-stop, echo, независимые скорость/тон, EQ, reverb, нормализация, транспортные fades и true-peak limiter. Electron/React сохранены. Звук основного плеера теперь выводит отдельный Rust-процесс через WASAPI; AudioWorklet в desktop не создаётся.

iOS не переносился. FFmpeg, кэш PCM, поиск, медиатека, анализ BPM/тональности и генерация `TransitionPlan` пока остаются в существующем сервере. Веб-версия и серверные WAV-предпрослушивания сохраняют TypeScript-микшер.

Код: `packages/audio-rust/`, мост `apps/desktop/src/rust-audio.mjs`, адаптер `apps/web/src/audio/desktop-engine.ts`. Описание сборки и границ — `packages/audio-rust/README.md`. Сырой отчёт, версии, SHA-256 исходников и бинарника — `docs/desktop-rust-audio-2026-10-30.json`.

## Численное сравнение

36 сценариев на 44,1/48 кГц, всего 84 прогона: 24 основных сценария по 3 раза и ещё 12 проверок крайних случаев по одному разу. На синтетическом детерминированном стереосигнале **все выходные PCM-сэмплы совпали побитно**, максимальное отклонение — 0 при допуске 0,00002. Состояния дек и события транспорта/переходов также сравниваются; порядок служебных `need`-запросов исключён из сравнения.

Проверены обычное воспроизведение, EQ/reverb/mono/balance, изменение скорости/тона, tempo glide, обмен басом, фильтр и echo, gap/delayed entry, изломы автоматизации внутри блока, loop/roll, tape-stop, forced finish, удаление играющей деки, pause/seek/gain/volume/stop. Дополнительно: настоящее ограничение пиков (около −11,25 дБ gain reduction), starvation/refill, поздний старт с fallback, укорочение/рост декодируемого файла и gapless.

Это проверка перечисленных путей, а не доказательство эквивалентности любого возможного плана.

## Производительность DSP

Windows x64, AMD Ryzen 5 9600X, Node 26.13.0, Rust 1.99.1, release/LTO, GNU target с bundled linker. V8 предварительно прогрет. Блок — 128 кадров. Ниже медианы трёх прогонов на 48 кГц; ускорение — отношение суммарного времени render TypeScript/Rust.

| Сценарий | Ускорение | TypeScript p99, мс | Rust p99, мс |
| --- | ---: | ---: | ---: |
| Обычное воспроизведение | 1,92× | 0,0206 | 0,0106 |
| EQ + reverb + mono/balance | 1,43× | 0,0205 | 0,0139 |
| Переход с изменением темпа | 1,77× | 0,1610 | 0,1132 |
| Loop/roll | 1,98× | 0,0277 | 0,0156 |
| Tape-stop | 1,99× | 0,0331 | 0,0257 |
| Независимые скорость/тон | 1,15× | 0,1423 | 0,1098 |

На 44,1 кГц обычное воспроизведение ускорилось в 2,18×, tempo-переход — в 1,94×, скорость/тон — в 1,18×. Первоначальная реализация lookup в sinc-resampler оказалась медленнее V8; устранён лишний `floor` для заведомо неотрицательного индекса без изменения PCM.

Замеры относятся **только к offline DSP**. Создание процесса, декодирование, IPC, base64, запись результата, Electron, драйвер и графика не включены. Это не ускорение приложения целиком и не сравнение общей памяти Electron. Дополнительные проверки крайних случаев служат проверкой корректности; их единичные времена не используются для вывода об ускорении.

## Проверка настоящего Electron и Windows

`node tools/check-rust-desktop.mjs` запускает скрытый экземпляр настоящего приложения с отдельным временным профилем и нулевой громкостью. Импортирует синтетические WAV через API, восстанавливает очередь и нажимает реальные кнопки интерфейса.

Успешно проверены:

- React → preload → Electron IPC → Rust → WASAPI, включая загрузку PCM.
- Play/Pause/Resume и сведение по кнопке Next с `transitionStart`/`transitionEnd`.
- Смена выхода и сохранение прежнего выхода при отказе HDMI-драйвера открыть формат (`0x88890008`). Затем успешно открыт выход Windows по умолчанию.
- Принудительное завершение только тестового Rust-процесса: приложение переходит на паузу, следующее пользовательское Play создаёт движок заново и загружает PCM.
- В коротком прогоне до принудительного завершения: 0 PCM underruns, 0 WASAPI underruns, 0 блоков дольше бюджета. Интервальный p99 DSP — до 0,035 мс.

Rust-процесс в момент замера: working set 17,73 МиБ, private memory 10,44 МиБ; CPU time 0,109375 с с его запуска. Эти цифры относятся к короткому muted-тесту и **не включают остальные процессы приложения**. Нативный executable — 1 068 032 байта; Electron, FFmpeg и yt-dlp сохранены, поэтому уменьшение всего установщика не заявляется.

Выходной резерв — 2048 кадров (42,7 мс на 48 кГц) плюс задержка Windows/драйвера. Это запас для музыкального плеера, не измеренная сквозная задержка. Устройство читает bounded lock-free ring; DSP, JSON и файловые операции не выполняются в device callback.

## Проверки и ограничения

Сборка desktop с нативным бинарником и текстами лицензий прошла. TypeScript-проверки web/desktop и Rust-тесты прошли. Автотесты desktop/web/core проверяются отдельно от численных сравнений; команды приведены в README ядра. В диагностике добавлены интервальные p95/p99 и счётчик пропусков Windows. Артефакты не устанавливались в пользовательский профиль и не публиковались.

Старые пользовательские изменения в рабочей папке сохранены. Rust toolchain установлен без изменения PATH; скрипт сборки находит Cargo в профиле пользователя.

Вокальные stems/voice-only echo пока не перенесены. Штатная текущая Windows-сборка отключает разделение голоса. Старый кэшированный stem-план контроллер преобразует через существующий защищённый full-mix fallback; это отмечается в диагностике плана и не останавливает воспроизведение. Ядро отклоняет непреобразованную stem-команду. Для кастомной сборки с разделением голоса ещё нужен перенос вокального пути. Анализ и планировщик на Rust — следующий этап, без их переноса нельзя называть всё общее ядро переписанным.

Не выполнены длительное прослушивание реальной библиотеки, Bluetooth/USB/сон/пробуждение на разных устройствах, проверка слабого ПК, численная матрица на 88,2/96 кГц и выпуск установщика. Короткий успешный тест не гарантирует отсутствие прерываний при любой нагрузке.
